## 二、已实测结论

### ① 3 针 5V WS2812 灯带 —— ✅ **通过**（2026-10-27）

| 项 | 结论 | 证据 |
|---|---|---|
| 板上的灯座丝印 | **G / V / S**（GND / 5V / 数据） | 用户现场读 |
| 接线 | 灯带 GND→G、5V→V、**DIN→GPIO5** | 用户现场接 + 本台账 |
| **数据脚** | **GPIO5** | 串口 `[WS2812] pin=5 count=8` |
| 能否点亮 | **能**（红→绿→蓝依次可见） | 用户现场观察 |
| 颜色顺序 | **GRB 正确**（发红显示红） | 三色轮测 + `LED_STRIP_COLOR_COMPONENT_FMT_GRB` |
| 3.3V 数据驱动 5V 灯带 | **能**，本次没踩到 VIH(≈3.5V) 门限 | 用户现场观察 |
| 亮度 | `64/255` 就能清楚看到 | 用户现场观察 |
| 保持 + 到点自动关 | 正常（20 秒后自动 `rgb=(0,0,0)`） | 串口 `(81273)` 行 |
| 5V 由板上 V 脚供 | 成立（否则不可能亮） | 同上 |
| 灯珠数量 | 用户表示目前只用 **1 颗**；测试按 `count=8` 发也正常（多发数据被忽略） | 用户口述 + 日志 |

**判定链**：`{"type":"command","payload":{"actions":[{"type":"ws2812","pin":5,"count":1,"rgb":[64,0,0],"duration":3000}]}}`
→ 串口出现 `[Command] 收到 1 个动作` → `[0] Action: ws2812` → `[WS2812] 新建灯带 pin=5 count=N` → `[WS2812] pin=5 count=N rgb=(r,g,b)` → 灯亮 → 到点自动 `rgb=(0,0,0)`。

> **这个动作是芯片级的，与板子无关**（只认"哪个脚 / 几颗 / 什么色"）。
> 所以瓦力、MOSS、Doly 以后**只要重编固件**，灯带/灯珠可以直接用同一套指令流，不用为每块板重写驱动。
> 反过来：**没重编的旧固件不认它**（会打 `未知动作类型: ws2812`）。
> 另：`count` 只是"要发几颗的数据"，物理上少几颗不会报错（多出的被忽略）。
> 这次买的灯珠与接线一并得到确认：**灯珠正常、G/V/S 接法正确**。

### ①-2 装进模型后的表现 —— ✅ **通过**（2026-10-27，装车后复测）

| 项 | 结论 | 证据 |
|---|---|---|
| 纯色（红/绿/蓝/白）@ 亮度 64 | 颜色正 | 用户现场观察 |
| 纯色 @ 亮度 128 | 更亮，仍可用 | 用户现场观察 |
| 呼吸（暖白 0→120→0） | **顺滑，无跳变/闪烁** | 用户现场观察 |
| 本轮固件侧错误 | **0 条** | 串口 50 条 `[WS2812]`，无 `E (` / `refresh 失败` / `创建失败` |

**呼吸怎么做的（可复用，固件一行没加）**：由**后台按 ~200ms 节拍连发 `ws2812`（不带 `duration`）**，
亮度 0→峰值→0 逐步推进，最后单独发一条 `rgb=[0,0,0]` 收尾。以后做剧场灯效照这个路子。

> ⚠️ 这条测试还暴露了一个与灯无关的问题：**后台进程当时已经退出了**，导致
> 设备连不上 `8003`（`EspTcp: Failed to connect, code=0x68`）、指令下发全部失败。
> 判据记在心里：**灯不亮先看后台在不在、设备在不在线**，别一上来怀疑灯。

## 五、踩过的坑（防复发）

| 坑 | 现象 | 教训 |
|---|---|---|
| **打开 COM8 会复位板子** | 抓串口时板子重启，刚发的指令没吃到（HTTP 仍回 200，是死连接骗的） | 流程必须是"先开串口 → 等它重连后台 → 再发指令" |
| 板上旧固件（Jul 21）**没有 `gpio`/`pwm` 动作** | 发 `{"type":"gpio"...}` 不会有 `GPIO n -> 1`；`application.cc` 新加的引脚级执行器 10-26 才有 | 判固件能力要**看板里那份 app 镜像**，别按源码假设 |
| `code_interpreter.cc` 的 `GpioWrite()` **不配输出** | 老固件的 `code_stream` 能跑，但引脚仍是输入，打了没反应 | 任何"打电平"前必须先 `gpio_config` 成输出（新 `gpio` 动作有 `EnsureOutput`） |
| `config.h` 的灯脚是从摄像头板抄的占位符 | 4 个"灯"脚全是摄像头数据脚 | **宏存在 ≠ 实物接在那**；引用前先量/先实测 |
| 自检开关忘了归零 | 编出来是自检固件，烧进去不联网 | 烧前 grep 一遍 `LINGKONG_SELFTEST` |
| 一次发多个"带 duration 的 gpio" | "到点回低"的任务被追加到**队列尾**，不是紧接下一条 | 要按顺序做动作就一条一条发，或算清队列顺序 |
