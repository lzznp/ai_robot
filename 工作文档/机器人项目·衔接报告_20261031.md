## 二、已确认的现象（一条一句 + 证据位）

### 2.1 MOSS（已全部打通）

1. **灯**：`GetLed()` 原来返回 `GpioLed(GPIO7)`，会用 **LEDC 4kHz PWM** 抢 GPIO7（第一组灯带的数据脚），表现为"上电后那颗灯珠常亮白"。改成 `NoLed` 后**上电全黑**，灯效全交后台指令。
2. **屏**：`SSD1306`，I2C port 0，SDA=GPIO2 / SCL=GPIO1，地址 **0x3C**，128×64。原厂固件支持它（镜像有 `Install SSD1306 driver`/`Adding OLED display`），我们这版原来 `GetDisplay()` 返回 `nullptr` 所以一直黑。
3. **摄像头**：**OV2640**（PID `0x26`），SCCB **0x30**（与屏 0x3C **不冲突**），DVP 8 位，抓帧 640×480（614400 B）。
4. **`0x3C` 是屏，不是摄像头** —— 老台账把 `0x3C` 判成 OV5640 的 SCCB，是错的。
5. `CAM_RST` 被焊在模块的 **EN** 脚上（同网挂 R17+C23），**软件不可控**，只能写 NC。

### 2.2 月球车（灯已结案）

6. 3 针灯带 G/V/S，DIN 接 **GPIO5**，颜色顺序 **GRB 正确**，3.3V 数据能驱动 5V 带。
7. `config.h` 里的 `LED_1..4`/`LED_STRIP` 是**占位符**（与摄像头脚完全重叠），**不是实物依据**。

### 2.3 后台侧（下一场要改的地方）

8. **角色映射不是硬编码**：`core/connection.py:_init_scene_dispatcher()` 从 SQLite `template_role_configs`（当前激活场景）读出来，`role_name → device_id`。
9. **`/api/command` 是原始管道**：`POST http://192.168.199.106:8004/api/command`，body `{"device_id":"...","command":{...}}`，`command` 原样 JSON 发给设备。**后台不需要懂引脚，只要会拼 §四 的 JSON**。
10. **`SceneDispatcher.dispatch_actions()` 只认 `tts` / `emotion` / `action` 三种**（`core/scene_dispatcher.py:148-195`），我们固件支持的 `gpio/pwm/ws2812/camera` 它**一个都不发**。
11. **`SceneDispatcher.process()` 只生成 tts 动作**（`:124-129`），`_build_system_prompt()` 也是极简版（只把角色名列一遍）。
12. **视觉链路缺 key**：`config.yaml` 的 `VLLM.ChatGLMVLLM.api_key = 你的api_key`（占位符），`/mcp/vision/explain` 会失败。
13. **后台进程会被会话回收**：用工具的后台任务方式启动，本场死了 2 次（第一次跑 PID 3480 那次也丢了）；用 `Start-Process` 独立进程才稳。

### 4.2 后台能用的 HTTP 接口

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/command` | POST | **主力**：`{"device_id":"...","command":{...}}` → 原样发给设备 |
| `/api/devices` | GET | 列出在线设备（返回 `device_id` / `ip` / `last_seen`） |
| `/api/text` | POST | 调试：走一遍 SceneDispatcher（LLM+TTS），需要设备在线 |
| `/api/scene/switch`、`/api/scene/stop` | POST | 场景切换 |
| `/mcp/vision/explain` | POST | 设备上传 JPEG + question，后台用 VLLM 解释（**缺 key**） |

### 4.3 固件认的"命令词汇"（后台照这个发，全在 `/api/command` 里）

```json
{"device_id":"58:e6:c5:5a:2f:fc","command":{"type":"command","payload":{"actions":[
  {"type":"gpio","pin":17,"level":1,"duration":1200},
  {"type":"pwm","pin":32,"freq":50,"pulse_us":2000,"duration":400},
  {"type":"ws2812","pin":7,"count":2,"rgb":[64,0,0],"duration":3000},
  {"type":"camera","op":"capture"},
  {"type":"delay","duration":300}
]}}}
```

| 动作 | 字段 | 语义 | 串口判据 |
|---|---|---|---|
| `gpio` | `pin` `level` `duration?` | 引脚电平；到点自动回落低 | `GPIO 17 -> 1 (hold 1200 ms)` |
| `pwm` | `pin` `freq` `pulse_us` 或 `duty` `duration?` | 舵机 500~2500µs / 调速占空比 | `[PWM] pin=32 freq=50 pulse_us=2000 bits=14 duty=…` |
| `ws2812` | `pin` `count` `rgb`[3] 或 `r/g/b` `duration?` | 灯带；不给颜色=关灯 | `[WS2812] pin=7 count=2 rgb=(64,0,0)` |
| `camera` | `op` = `capture`/`explain` | 抓一帧 / 抓帧并上传视觉接口 | `[CAMERA] 抓帧成功` + `mmap_buffers_[..].length = 614400, frame.width = 640, frame.height = 480` |
| `tts` | `text` | 直接播报 | `[Command] TTS: …` |
| `emotion` | `emotion` | 表情 | `Emotion: …` |
| `servo` / `move` | 老动作 | 留着不删，**后台别用** | — |

> `command` 的 payload 里还可以直接带 `"tts":"文本"` 或 `"emotion":"happy"`（顶层字段），效果等同对应动作。

## 五、下一场怎么干（**后台主线**）

**主线：让后台能按场景生成"指令流"，把语义变成 §4.3 的动作序列，并真的下发到设备。**

建议顺序（一次只做一件）：

1. **让后台稳定跑起来**
   `Start-Process` 独立进程启动（见速查卡），确认 8000/8003/8004 + `/api/devices` 有设备。
   ⚠️ 别用工具的后台任务，会被回收。

2. **打通"后台 → 设备"的指令流（最值钱的一步）**
   现状：`SceneDispatcher.dispatch_actions()` 只认 `tts/emotion/action`，**发不出 `ws2812`/`gpio`/`camera`**。
   目标：让场景产出的动作能落到 `/api/command` 那条管子上。
   判据：从后台发一条 `{"actions":[{"type":"ws2812",...}]}`，设备串口出现 `[WS2812] …` 且**实物变色**。

3. **把"语义"做成后台能力库**
   例："亮红灯" → `[{ws2812,pin:5,count:1,rgb:[64,0,0]}]`；"呼吸" → 按 200ms 节拍连发一串 `ws2812`。
   ⚠️ 别往固件里塞语义（已拍板）。

4. **视觉**（可选，取决于要不要"天眼"）
   填 `VLLM.ChatGLMVLLM.api_key`（智谱 `glm-4v-flash` 有免费额度）或换 `QwenVLVLLM`，然后走 `camera {op:"explain"}`。
   判据：设备串口 `[CAMERA] explain 返回: …` 有内容而不是报错。

5. 顺手要修的已知小坑
   - `esp32_simulator.py` 里的三个设备 ID 是**错的**（别照抄）
   - 冒充连接（如 `_probe_role_map.py`）会在后台留下**僵尸设备条目**，表现为 `/api/devices` 里多一台不在线的
   - `SceneDispatcher._build_system_prompt()` 是极简版，做剧场要重写
