## 二、已确认的现象（一条一句 + 证据位）

### 2.1 瓦力（**已结案**，详表见 `瓦力-硬件台账.md`）

1. **板型 = `qebabe-xiaoche`**。证据：dump 内字符串 `./main/boards/qebabe-xiaoche/compact_wifi_board.cc`。
2. **原厂固件版本**：`xiaozhi 2.1.0`，编译 `Jul 12 2026 15:02:05`，IDF v5.5.4，运行分区 `ota_0`。证据：dump app 描述段 @0x20020。
3. **卖家的 MCP 增强已包含在作者开源仓库里**：`self.motor.*`(21 个) + `self.lamp.*`(3 个) 与仓库 `AddTool` 一一对应；板子固件只多出 3 个 `screen.*` 和 `assets.set_download_url`（= 更新的上游底座）。
4. **真实电机接线：电机 A = GPIO13/14，电机 B = GPIO17/18**（各两路，方向正确）。证据：`pin_scan` 逐脚实测。
5. **真实舵机接线：左手 = GPIO11，右手 = GPIO12**。第三个舵机未找到，已挂起。
6. **`GPIO18` 不是灯，是电机 B 的一路 IN** ⇒ `self.lamp.turn_on` 会让电机 B 转、灯不亮。这是卖家资料与实物不符的直接后果。
7. **板上电源开关 = 电机/舵机供电**；不打开也能连 COM（逻辑由 USB 供电）。
8. **屏 = SSD1306 I2C（41/42），128×32**。按 64 初始化会"上面少一块"。证据：作者 `config.json` 默认 `CONFIG_OLED_SSD1306_128X32=y` + 实测。
9. **灯：30 个候选脚的静态高电平全扫过，没有一个能让灯亮** ⇒ 判为没接线 / 不存在。
10. **官方云状态**：设备仍算"已激活"，但控制台里智能体被用户删除 ⇒ 不弹激活码、控制台看不到它。

### 4.4 "唤不醒"的两个根因（已修，别再犯）

1. **分区表缺 `model` 分区** ⇒ esp-sr 不打包唤醒词，启动报 `MODEL_LOADER: Can not find model in partition table`。
   证据：`managed_components\espressif__esp-sr\CMakeLists.txt:78-85` 要求 `--partition-name model`。
   修法：`partitions\wali_16m.csv`（model 960K / ota_0 3M / ota_1 3M / assets 6M）；修好后日志有 `Successfully load srmodels`。
2. **`main\audio\audio_service.cc` 里 MOSS 时期遗留的"强制关麦"**：启动后无条件 `codec_->EnableInput(false)`（日志 `🔇 麦克风已强制关闭`），随后 `AudioInputTask` 报 `Should not be here, bits: 4` 并退出。
   修法：已删。**它不是** MOSS 台账 §七 设计的"软开关"（那个要在 `EnableVoiceProcessing`/`EnableWakeWordDetection` 里加总闸，尚未实现）。

### 4.5 BOOT 键行为（容易误会成 bug）

| 操作 | 结果 |
|---|---|
| 单击 BOOT | 开始/结束对话（会打断唤醒检测） |
| **长按 BOOT（≥2s）** | **重新配网**（进 AP 模式）→ 此时唤不醒是正常的 |
| 重新上电 | 恢复正常 |

### 4.6 其它环境坑（都踩过）

- 本机 `pwsh` 实际是 **Windows PowerShell 5.1**：`Get-Content` 读 UTF-8 中文会乱码、行号会错；**改文件一律用编辑器工具或 `.NET ReadAllText/WriteAllText(UTF8)`**，别用 `Get-Content | Set-Content`。
- `idf.py -DSDKCONFIG=sdkconfig.xxx` 里名字**别带点**（`sdkconfig.lingkong` 会被解析成任务名，报 `unknown target '.lingkong'`）。
- **开着 `idf.py monitor` 时我这边无法烧写**（端口被占，`PermissionError(13)`）。
- 两种固件同名 `build\xiaozhi.bin` 会互相覆盖 ⇒ **编完立刻复制进 `_archive\` 带日期+用途命名**。
- 工作区**没有 git**，无回滚点。

## 七、我的错（本场判断失误，逐条认）

| # | 错在哪 | 真实情况 | 教训 |
|---|---|---|---|
| 1 | 把作者 `config.h` 当"实物引脚"用，直接写进台账 v1 | 卖家的板子接线和作者资料对不上（电机在 13/14 + 17/18，18 是电机不是灯） | **开源代码 ≠ 你的实物**；能实测就实测 |
| 2 | 第一版扫描只测 8 个脚，得出"都没反应" | 当时**电源开关没开**（电机没供电），而且真脚不在那 8 个里 | 测试前先确认"被测对象有电" |
| 3 | 扫描固件 v1 每测完一个脚 `gpio_reset_pin()` | 这会把脚变成"输入+上拉" ⇒ 那根线还是高电平 ⇒ 电机继续转，分不清是谁在控制 | **测完保持输出低**，别 reset |
| 4 | 扫描固件 v1 没存进度 | 在 GPIO4 上导致复位后，一按 BOOT 又从 GPIO1 开始，永远卡死 | 长扫描要**把进度存 NVS**，崩溃能续 |
| 5 | 早期认为"8 个脚全没反应、舵机没接线" | 是固件 bug + 没开开关，不是硬件 | 结论要能解释**所有**观察，解释不了就是自己错了 |
| 6 | 上一轮把"接后台"想当然成"改个地址就行" | 后台**根本没在跑**，`config.yaml` 的 LLM 密钥还是占位符 | 说"要接后台"前先 `Test-NetConnection` 确认它在听 |
