## 二、已确认的现象（一条一句 + 证据位）

1. **I2C 引脚是 `SDA=GPIO2 / SCL=GPIO1`，现行 `config.h` 正确，别再改。**
 证据：自检 1/6 扫到 `0x3C`；2/6（对调）**一个设备都没有** —— 反向对照成立。
2. **`0x3C` 是摄像头（OV5640 的 SCCB 地址），不是 OLED 屏。**
 证据：网表 590 个器件里**没有任何显示驱动 IC**；用户刷原厂固件 + 去掉延长线后**摄像头正常**。
3. **MOSS 板上没有屏。** ⇒ 能力清单里不该有 `screen_emotion`/`screen_text`；H4 只是把 I2C 引出来，可外挂 OLED。
4. **双步进电机全链通过。** 证据：128 步实测 `2230 ms / 2140 ms`（设定 60 步/秒，理论 2133 ms）。
5. **摄像头必须插 `U13`（2×10 / 20 针 / 2.54mm）**，不要插 `FPC1`。
 证据：`FPC1` 的信号 `NET_8…NET_26` **只到 H1 排针，与 U8 无一相连**；`U13` 才带 `CAM_VSYNC/HREF/XCLK/PCLK/D0-D7/PWDN/RST` + `GPIO01/GPIO02`(SCCB)。
6. **摄像头故障的真凶是接插件（延长线），不是模组。**
7. **3 灯组（GPIO7 / 2020 封装 / `5V_LED2020`）曾正常点亮**，后被用户弄烧（现只剩 1 颗亮绿或蓝，后两颗不亮）。
 **2 灯组（GPIO48 / 4020 / `5V_LED4020`）不亮** ⇒ `H6 ↔ FMH2` 至少缺一根线。
8. **电机日志顺序颠倒的根因已定位并修掉**：`esp_rom_delay_us` 忙等 + 电机任务绑 core0、优先级 5 ⇒ 抢占同核的 `app_main`，日志被打到动作之后；**生产固件里会卡住音频**。
9. **ADC 有读数**（电池 GPIO8 ≈ 2506，USB GPIO6 ≈ 2988），但**还没做拔插 USB 的对照**。
10. **板子的 build 目录不能再跨机器/跨路径复用** —— CMakeCache 记的是绝对路径。

## 四、事实（下一场直接用，别重查）

### 4.1 MOSS 引脚表（网表 + 实测双确认）

| GPIO | 连到 | 用途 |
|---|---|---|
| 0 | SW2 BOOT 键 | 下载/配网键（实测正常） |
| **2** | H4.1 + U13.17 + R16→3V3 上拉 | **I2C SDA** |
| **1** | H4.2 + U13.19 + R15→3V3 上拉 | **I2C SCL** |
| 3 / 4 / 5 | U6.11 / U6.12 / U6.14（74HC595） | 步进 SHCP / STCP / DS |
| **6** | R21→USB_5V、R24→GND | **USB 插入检测（分压）—— `config.h` 里没定义** |
| 7 | H5.2 | 灯带1（3 颗 / 2020） |
| 8 | R20→VBATT、R23→GND | 电池 ADC1_CH7 |
| 9 / 10 / 11 | U12.2/3/4（NS4168） | I2S 音频 |
| 12 / 13 | H3.1 / H2.1 | 麦克风 PDM（**外挂**，板上没有） |
| **14** | H3.2 | 空置 —— `config.h` 里没定义 |
| 48 | H6.2 | 灯带2（2 颗 / 4020） |

排针：`H2` GPIO13/3V3/GND｜`H3` GPIO12/GPIO14/GND｜`H4` GPIO02/GPIO01/3V3/GND｜
`H5` +5V/GPIO7/GND｜`H6` +5V/GPIO48/GND。另有 `U13`(20 针摄像头)、`FPC1`(26 针 0.5mm，只通 H1)、`H1`(40 针)。

### 4.2 自检固件的交互（已实测可用）

```
上电 → 自动跑 0/6 并停住
单击 BOOT（<0.8s） = 翻下一项（只打印标题，不执行）
长按 BOOT（≥0.8s） = 执行当前项
判据：出现 ">>> 执行: x/6" 才算真执行
```
7 项：0 系统信息 / 1 I2C A(SDA2,SCL1) / 2 I2C B(对调) / 3 电机1 / 4 电机2 / 5 灯组(真 WS2812 RMT) / 6 ADC

### 4.4 `motor_control.c` 修的 6 处

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| B1 | 两电机抢同一队列，收到别人的命令就丢 | 约一半命令消失 | 每电机一个队列 |
| B2 | `motor_set_phase()` 覆盖整个 595 字节 | 两台不能同时转 | `hc595_modify()` 只改自己半字节 |
| B3 | `hc595_write()` 无互斥 | 并发时移位时钟交错 | 加互斥量 |
| B4 | `1000/speed` + `pdMS_TO_TICKS` 量化 | 60 步/秒 跑成 100 步/秒 | 见 B6 |
| B5 | 日志 0 基/1 基混用 | 「电机2」打成「Motor 1」 | 统一 1 基中文 |
| B6 | 忙等阻塞同核 | 日志错序；生产固件会卡音频 | `vTaskDelay` 让出 CPU + `delay_acc_us` 累积补偿 |

- 两种固件同名 `build\xiaozhi.bin`，**会互相覆盖** ⇒ 编完立刻复制进 `_archive\` 并带日期+用途命名。

## 七、我的错（AI 的判断失误，逐条认）

| # | 错在哪 | 真实情况 | 教训 |
|---|---|---|---|
| 1 | 把 `0x3C` 判成 OLED 屏 | 是摄像头（OV5640），板上根本没有屏 | 扫到地址 ≠ 知道是谁，要先确认"板上有没有这个器件" |
| 2 | 用 `FPC1` 的证据解释"摄像头扫不到" | 前半对（FPC1 确实不接 MCU），**后半错**（摄像头不在 FPC1 上） | 结论方向对，也可能是用错证据凑出来的 |
| 3 | 网表推断"两组灯都没接 GPIO" | GPIO7 那组是通的 | **网表只能证明"无铜箔走线"，证明不了"无锡桥/跳线"**；实物优先 |
| 4 | 修 B4 时引入新 bug | `pdMS_TO_TICKS(16)` 在 100Hz tick 下 = 10ms，60 步/秒跑成 100 步/秒 | 改延时先算清 tick 粒度 |
| 5 | 修 B4 的第二版用忙等 | 抢占同核，日志错序，生产会卡音频 | 高优先级任务不许忙等 |
| 6 | 灯组测试最初设计成"静态电平翻转" | 对 WS2812 毫无意义，等于没测 | **判据写不出来就别写测试** |
| 7 | 没让用户分组测灯就让他判"亮没亮" | 两组一起亮，分不清是哪组 | 测试必须能"分辨"，不只是"触发" |
