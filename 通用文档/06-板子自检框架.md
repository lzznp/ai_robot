# 06 · 板子元件自检框架（通用：给任何一块板加"验硬件"的固件）

> 版本 v1 ｜ 2026-10-22 ｜ 来源：MOSS 550W + 月球车（lingkong）两台的真实实现与踩坑
>
> **这份是接口，不是资料。** 看完就能给一块新板加自检。
> **它解决的问题是已经发生的**：应用层固件把"元件坏没坏"淹没成"连不上服务器"，导致 MOSS 的 I2C 定义、电机链、摄像头、灯组排查全部绕远路。

---

## 一、为什么要有（一句话判据）

**应用层工具判不了元件层。**

出厂固件 / 后台控制台判"能不能用"的链条是：
`WiFi 连上 → 后台在线 → 设备响应`
这条链上任一环坏掉，现象都是同一个："连不上 / 没反应"。于是**元件问题被淹没**。

自检固件把链条砍到只剩一根 USB 线：
`芯片在跑 → 串口能打印 → 逐项驱动物理外设`
⇒ 任何一项失败，只可能是三件事之一：**① 接线 ② 器件 ③ 引脚定义写错**。

**什么时候该写自检**：拿到一块"硬件没问题但不敢确认"的板（新板、二手板、自己焊的板、换了机器记不清接线状态的板）。
**什么时候不该写**：板上什么都没有、或者只是改应用层文案。

## 二、分工（一条线切开，别混）

| 层 | 位置 | 内容 |
|---|---|---|
| **引擎（共用）** | `esp32-firmware\components\selftest\` | 横幅、BOOT 键单击/长按、换项/执行、通用打印与 I2C 扫描 |
| **助手（共用）** | `components\selftest\selftest_helpers.c` | `st_print_sep` / `st_print_sysinfo` / `st_i2c_scan(port,sda,scl,why)`（`selftest_helpers.c:87`） |
| **项表（每板一份）** | `main\boards\<板>\selftest_items.c`(或 `.cc`) | 只回答"这张板有哪几项、每项怎么测、**看到什么算通过**" |

引擎 API 只有三个类型/函数（`components\selftest\selftest.h`）：

```c
typedef struct { const char *title; void (*run)(void); } st_item_t;
typedef struct { const char *board_name; int boot_gpio;
                 const st_item_t *items; int item_count; } st_config_t;
void st_run(const st_config_t *cfg);   // 不返回
```

**交互固定**（`selftest.c:24` 长按阈值 800ms、`:94` 判定、`:99` 换项）：
上电自动跑第 0 项 → **单击 BOOT = 换下一项（只打印标题，不执行）** → **长按 ≥0.8s = 执行当前项**。
**只有出现 `>>> 执行: x/N` 才算真执行过**（`selftest.c:53`）—— 标题行不算。

## 三、三步给新板加（照抄）

### 第 1 步：写项表 `main\boards\<板>\selftest_items.c`（C）或 `.cc`（C++）

**用 C 还是 C++ 看板级代码**：板级是 C++ 类（如月球车的 `MotorControl`/`ServoControl`）就写 `.cc`，用 `extern "C"` 导出配置：

```c
static const st_item_t kXxxItems[] = {
    {"系统信息（芯片 / MAC / 内存）", item_sysinfo},
    {"I2C 扫描：port1  SDA=GPIO21  SCL=GPIO14", item_i2c},
    /* ... 一项一行，标题写清"引脚 + 动作" ... */
};
extern "C" const st_config_t xxx_selftest_config = {   // C 文件去掉 extern "C"
    .board_name = "板名（写人能认的名字）",
    .boot_gpio  = (int)BOOT_BUTTON_GPIO,
    .items      = kXxxItems,
    .item_count = (int)(sizeof(kXxxItems) / sizeof(kXxxItems[0])),
};
```

**每一项的硬要求**（写不出第 3 条就别写这项）：

1. 自己初始化自己的外设（别依赖板子构造里的初始化 —— 自检模式下那些**故意不跑**）
2. 分组测，能**分辨**是哪一路坏（例：两组灯要**分开点亮**，不能一起亮）
3. 结尾 `printf` 出 **判据**：看到什么算通过、每种异常指向哪个器件/哪根线

**不写进项表的两种情况**（都是踩过的）：
- **判据写不出来**：例：灯板型号未知、板级也没有驱动代码 ⇒ 点不亮无法区分"没接/型号不对/驱动没写"⇒ 不写这项，写进文件头注释说明原因。
- **一项验不了两个变量**：要分开成两项。

### 第 2 步：`main\CMakeLists.txt` 里那个板的块加源文件 + include 目录

```cmake
elseif(CONFIG_BOARD_TYPE_XXX)
    set(BOARD_TYPE "xxx")
    set(BOARD_EXTRA_SOURCES
        "${CMAKE_CURRENT_SOURCE_DIR}/boards/xxx/<板级源文件>.c"
        "${CMAKE_CURRENT_SOURCE_DIR}/boards/xxx/selftest_items.c"   # ← 加这行
    )
    list(APPEND SOURCES ${BOARD_EXTRA_SOURCES})
    list(APPEND INCLUDE_DIRS "${CMAKE_CURRENT_SOURCE_DIR}/boards/${BOARD_TYPE}")  # ← 否则找不到 config.h
```

现成例子：`main\CMakeLists.txt:232`（月球车）、`:246`（MOSS）。**component `selftest` 不用手动 REQUIRES** —— IDF 的 `main` 自动依赖所有组件。

### 第 3 步：板子 `config.h` 加开关 + 板子构造里分支

`config.h`（`#define` 开关，注释里写清 0/1 各是什么）：

```c
#define XXX_SELFTEST 1   // 1 = 上电直接进自检（不启动 WiFi/Application）；0 = 正常固件
```

板子 `.cc` 构造函数最前面分支，**自检时不要初始化屏/I2C/WiFi**：

```cpp
XxxBoard() : ... {
#if XXX_SELFTEST
    st_run(&xxx_selftest_config);   // 不返回
#else
    ...正常初始化...
#endif
}
```

现成例子：`main\boards\moss_550w\board_moss_550w.cc:85`、`main\boards\lingkong-s3-moc-cam-1.54tft\lingkong-s3-moc-cam-1.54tft.cc:208`；开关在 `moss_550w\config.h:17`、`lingkong...\config.h:13`。

**编译 + 烧写**（板型在 sdkconfig 里选，别指望 `-D` 传）：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. 'C:\Espressif\tools\Microsoft.v5.5.4.PowerShell_profile.ps1'
cd D:\study\jiqiren\ai_robot\esp32-firmware

idf.py -B build_<板> -DSDKCONFIG=sdkconfig_<板> build
```

## 四、判据怎么写（这是整篇最要紧的一节）

**判据 = "我在串口上看到什么" + "我在实物上看到什么"。** 两样都要有，缺一不可。

| 写法 | 例子（真实） | 为什么这样 |
|---|---|---|
| ✅ 好 | `电机2: 正转 128 步` → 判据：**转了 = 595/ULN2003/电机全通；不转但发烫 = 相序或某一路坏；完全不响 = 查 +5V 与 /MR /OE** | 三种现象分别指向三段器件，人能直接对号 |
| ✅ 好 | `I2C 扫描 A/B 对调` → 判据：**哪一次扫到 0x3C 就照哪次写 config.h** | 反向对照，能把"引脚定义写反"和"器件坏"分开 |
| ✅ 好 | 屏：满屏红→绿→蓝 | 颜色对了 = SPI + 驱动 IC + 背光 + IO 扩展全通，一秒钟判完 |
| ❌ 差 | "翻转 GPIO 电平原点被占用" | 对 WS2812 毫无意义（灯珠要 800kHz 数据流），等于没测 |
| ❌ 差 | "两组灯一起亮" | 分不清是哪组没接 —— 测试必须能**分辨**，不只是**触发** |
| ❌ 差 | 没有判据、只打印 OK | 那是日志，不是测试 |

**三条护栏**：
1. **扫到地址 ≠ 知道是谁** —— 先确认"板上有没有这个器件"。MOSS 把 `0x3C` 当成 OLED 屏，实际是摄像头 OV5640 的 SCCB。
2. **网表只能证明"没有铜箔走线"，证明不了"有没有锡桥/跳线"** —— 实物优先。
3. **判据必须是"能分辨"的**：一项测试如果两种故障现象一样，就把它拆成两次执行。

## 六、踩过的坑（写下来防复发）

| 坑 | 现象 | 教训 |
|---|---|---|
| 共享组件改了没重编另一台 | 改完只有一台编过，另一台其实已坏 | **动 `components/selftest/` 后，所有用到它的板都要重编一遍** |
| 往 `config.h` 里塞端口宏给组件用 | `I2C_PORT` 展开成 `I2C_NUM_0`，而该板 config.h 没 include i2c 头 ⇒ 编译报未定义 | **项表里直接传端口号数字**，别为了一个宏给 config.h 加依赖 |
| C++ 里用 `= {0}` 初始化含枚举的结构体 | `invalid conversion from 'int' to 'i2c_addr_bit_len_t'` | **`.cc` 文件里一律 `= {}`** |
| 自检模式下板子构造照常初始化屏/WiFi | 引脚被占、I2C 总线抢不到，项表测的就不是真实状态 | 自检分支里**只调 `st_run()`**，其它初始化留给各项自己 |
| 用"标题行出现"当执行过的证据 | 只打印标题、没执行，人以为跑过了 | 只认 **`>>> 执行: x/N`** |
