# 04 · 做 LLM 助手 / agent 产品的设计判据

> 版本 v1 ｜ 2026-09-23 ｜ 来源：多个项目的**实测**（与语言、框架无关，Go / Python 都成立）
> 用途：设计任何"LLM 参与干活"的产品时，先拿这几条对一遍。**判据，不是资料。**

---

## 一、九条判据

| # | 判据 | 为什么（实测换来的） |
|---|---|---|
| 1 | **脑 / 手 / 嘴 三分** | 脑＝LLM 出判断；手＝确定性脚本干活；嘴＝本地渲染（**0 token**）。**三者不许互相越权** |
| 2 | **硬规则进代码、软规则进文档** | 确定性判定（如"招聘方与候选人同集团＝不合格"）写进本地校验函数：**0 token、100% 执行、可单测**。写进给 LLM 看的规则文档＝**它会漏**（实测：3 个同集团候选人，细筛只提到 **1** 个） |
| 3 | **记录不可改、展示可重算** | 判断结果一旦落盘就是**账**；界面上的东西可以从账**重算**，但**不许改账** |
| 4 | **判断对话化** | 重要结论由助手给出「**态度 + 理由**」，**等人拍板**，不替他决定 |
| 5 | **闸门挪进门里** | 关键词门表**漏一个词，就等于代码替人拍了板**；**没把握时当场反问**，而不是继续加词 |
| 6 | **不许假成功** | 跑完**先判真产出**，再写状态（见 `01-协作方法.md` §一） |
| 7 | **可替换的东西，待在边界外面** | 宿主软件（Rhino / Blender / FreeCAD…）、前端壳（Streamlit / Wails…）**将来会换、会增加** ⇒ **宿主名只许出现在"手"那一层（适配器），UI 逻辑不许写进页面函数**。**成本为零**（写代码时的一个习惯）；**不建抽象层**（那违反"够用就停"） |
| 8 | **上下文必须有上限** | 让"会话"无限堆积 ⇒ 输入量**随对话变长没有上限**。（实测：曾"**两头都在攒**"——运行时会话一轮轮往上堆，**又**每轮把盘上最近若干轮重喂一遍 ⇒ 同一段话喂两遍。）正解＝**每轮现拼一张要点卡 ＋ 只带最近 N 轮、且每轮截断** |
| 9 | **模型猜错 → 喂事实，别拉长历史** | 实测：壳其实"全都知道"（焦点、递来的每一页、手上有哪几个岗），却只喂了两样 ⇒ 模型只能猜、**当场断言错**。**修法不是把历史拉长，是把"壳已经算好的事实"喂进去**（全本地算，0 次模型调用） |

## 二、可直接照做的六个"形状"（都是实测出来的，不是设计出来的）

| 形状 | 怎么做 |
|---|---|
| **知识外置** | 站点/领域知识写成数据文件，每条带 `locate / action / verify / pits / status` **+ 实测日期**。⚠️ 例：某站点**绝不能用页面摘要判断弹层**（摘要只截前 3000 字，弹层文字在页面末尾 ⇒ **必然误判**）——**这种知识是实测换来的，推理得不出来** |
| **改版自动降级链** | `verify_site` → 探测到基线缺失 → 事件 `site_changed` → **本任务降级为纯 LLM 现场推理（不注入已过时的知识）**。比"等厂商发版"抗变 |
| **强制 verify** | 执行动作后**必须 verify**；`ok=true` 但 `verify=false` **不许静默通过** —— 否则"带着没设上的条件跑"，结果会被误读成事实。<br>**这是防止错误的事实在项目里传播，比防 bug 高一层** |
| **置信度闸门** | 高置信自动写回 / 低置信**等人确认**，且带 `version + history`（**可回退**） |
| **上下文要点卡（每轮现拼）** | 每轮**新会话**，另拼一张卡：①**人设**（单独文件）②**输出纪律**（每条都挂实测出处）③**【你没有手】常驻** —— 治"假执行"，代价**明码标价**（≈**200 字/条消息**），换"漏了也安全" ④**场景块**（落点／台账／最近结论）⑤**最近 N 轮、每轮截断**（实测：6 轮 × 每轮 120 字）。⇒ **上下文靠拼，不靠会话** |
| **流水三分** | 一个流水文件里**混着三种东西**：①人说的话 ②**壳塞进去的原始材料** ③**机器出的结论行**。界面**必须分开**，否则聊天里掺满内部日志（实测：某 chat 页面的老毛病正是"**没区分管道里的东西和人说的话**"）。判 kind 要**"读的时候现推"、不在写的时候记** —— 这样能把已经攒下的旧账一起治好，且不用改写入路径 |

## 三、人机协同的边界怎么定（不是靠提示词，是靠工具面）

1. **自动化程度是产品决策，不是技术决策。** 先定"哪几个动作永远由人拍板"，再谈模型能力。
2. **能力边界＝注册了哪些工具**：不注册＝不挂载＝调用被拒，模型**连"能这么干"都不知道**
   （见 `02-DSH-SDK口径.md` §一）。
3. **高风险动作（对外发消息、改数据、花钱）必须过人的闸门**；低风险动作（读、算、草拟）可以让它自己跑。
4. **别走"LLM 生成代码字符串 → 直接执行"**：没有工具面、没有权限边界、出错难回滚。
   正确形状：**LLM 出结构化意图（JSON/参数）→ 本地代码执行**。
