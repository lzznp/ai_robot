# 01 · 协作方法（通用：跨对话 / 跨机器 / 跨项目）

> 版本 v1 ｜ 2026-09-23 ｜ 来源：多个项目的**真实踩坑**，不是通用建议
>
> **本目录（`通用文档\`）是通用件**：换电脑、换工作区、换项目都直接用这三份。
> **`参考文档\` 是历史件**：4 份，其中两份内容**大量重复**、一份是 3D 项目的历史。**新对话不必读**，只在追溯历史时读。
>
> **这份是接口，不是资料。** 新对话读它就能开工，不必读任何历史文档。
> **什么时候该改它**：某条做法被实测证伪时 —— 改完在文末记一行。
> **什么时候该删它**：当它开始出现"未来的设计"、或与实测冲突 —— 那说明它在退化成资料，先瘦身。

---

## 一、三条规矩（不可协商）

1. **一次只谈一件事。**
2. **只解决已经发生的问题** —— 提方案必须先写清"它解决哪个已发生的问题"，**写不出来就不许提**。
3. **够用就停**，不为五年后设计。

**外加一条地基**：**判断错不罚、不诚实必罚。**
说"已落盘"就必须真落盘；查不到就说查不到；**绝不编**。

**不能假成功**：跑完**先判有没有真产出**，再写状态。它嘴上说"我做完了"不算数；声称与实际不符时**当场纠正**。（实测抓到过：它说"我记下了"，面板当场打脸。）

---

## 二、对话衔接：关一个 / 开一个

**铁律**：关掉一个对话之前必须留下文档；打开一个新对话之前必须先读文档。
**新对话永远不靠"继承老对话的记忆"起步**——只靠交接产物。

**什么时候该收尾**：
① 完成一个阶段/里程碑 ② 对话明显变钝（回看要翻很久、开始重复问已答过的问题）
③ 上下文将满 ④ 换工作区/换项目/换主题 ⑤ 即将换角色阶段。

**一个对话只做一个阶段。做完就停、就交接，不恋战。**

### 交接包固定骨架（照抄，宁可短不可缺）

1. `★ 速查卡` —— 新对话**只读这一页**就能开工：环境口径 + 现盘状态 + **下一场第一件事**
2. `本场做完的事`
3. `已确认的现象` —— 一条一句 + **证据位**（`文件:行号` / 路径 / 时间戳）
4. `已拍板：挂起不修清单` ← **最重要**，防下一场重开已决事项
5. `事实（下一场直接用，别重查）` —— 全部带行号/路径
6. `下一场怎么干（照这个干）`
7. `三条规矩`
8. `我的错` —— 判断失误也要写（**判断错不罚、不诚实必罚**）
9. `收尾复盘` —— 由**人**写一两句（AI 写不了这个）
10. `新开场白` —— **可直接复制**给新对话，写明"只读哪几份、别读哪些"

### 两条硬规矩

- **只写"已发生"的事**；未发生的进"以后再说"，**不展开**（这就是"够用就停"）。
- **每份报告必须回答"下一场第一件事是什么"** —— 答不出来，它就已经是资料而不是接口了。
- **新对话只读最新的那一份**；**老报告别读**（含过期口径，会带偏）——宁可让它按行号去台账里翻。

## 三、防"资料黑箱膨胀"

**症状**（真实发生过）：文档目录 40+ 份、单份 `PROGRESS.md` 123 KB、决策表 80 KB —— **越写越厚，新对话读了还被过期口径带偏**。

**两层分离（核心）**

| 层 | 文件 | 谁看 | 规则 |
|---|---|---|---|
| **过程台账** | `现象清单.md`（§1…§N，**只追加**） | 自己 / 要细节时 | 每条现象**带证据锚点**（`文件:行号` / 路径 / 时间戳） |
| **衔接报告** | `xxx·衔接报告.md` | **新对话只读这份** | **薄**、结论层、第一页＝速查卡 |

**四个根因 → 四个做法**

| 根因 | 做法 |
|---|---|
| ① 没区分"结论"和"过程" | 两层分离；**报告必须一页能读完** |
| ② 没有证据锚点 ⇒ 每次重查 | 每条结论后挂 `文件:行号` / 路径 / 时间戳 ⇒ **结论可复核** |
| ③ 没有"挂起清单" ⇒ 已决事项被反复重开 | 报告必带"挂起不修清单"，下一场**不许重开** |
| ④ 报告里写"未来的设计" ⇒ 越写越厚、很快过期 | **只写已发生的事** |

## 四、省 token（都是实测换来的）

| 做法 | 为什么 |
|---|---|
| **任务书一次把事实给全**（路径写死 + 现状卡） | 只给三个文件路径让它自己找路，实测烧掉 **≈25,478 token**；一次分析 8 轮 / **139,075 token** |
| **别让它写长文/大 HTML** | 无长度上限时一回涨到 **13,065 字符**、占整次开销 ~15% ⇒ 改成"只交短 JSON 字段 + **本地渲染**"（0 token） |
| **汇报只报摘要**（固定四行） | 完成度 / 质量结论（对照验收标准）/ 与设计的偏差 / 下一步建议。**决策者不读实施代码** |
| **能关的工具都关** | 每轮固定开销：首轮前缀 ≈**7,430 token**；工具面 ≈**6,481 token/轮** |
| **上下文长了就换对话** | 一个对话从头干完大项目 ⇒ 上下文爆炸必然质量下降 |
| **一次别让它写两个大文件** | 会撞单次输出上限 ⇒ **两个文件全丢** |
| **`max_tokens` 给小了会截断** | 实测 8192 截断过 ⇒ 给足（我们给 16384） |

**工具面 = 物理边界**：关掉＝不挂载＝调用被拒。**能力由设计决定，不由技术决定。**
**量级参考**（估预算）：单步短任务 10–70 秒；一次真采集 70 分钟。

## 五、角色分工（单人项目也照做，角色动作不能省）

| 角色 | 职责 | 边界 |
|---|---|---|
| **决策者**（经理） | 讨论意图、确认设计、最终拍板 | 不读实施代码；只收摘要汇报；只在**业务取舍 / 设计偏差 / 阻塞**三件事上介入 |
| **架构**（小组长） | 读实施成果判质量 → 拆任务 → 派发 → 验收 → 报摘要 | 不写实施代码 |
| **实施**（组员） | 读任务 → 编码 → 验证 → 提交 → 回报 | 只做分配任务，不擅自扩大范围 |

## 六、什么时候该问"网页版大模型"

判据一句话：**"这个问题的答案，能不能在你机器／你的文件里被核对？"**
能 → 本地这套去查；不能 → 问网页版；两类都涉及 → **让它出选项，本地去验**。

三条用法：
1. **它出选项、本地出证据**：让它给 3 个候选 + 每条带出处；拿回来只做一件事——读代码／跑最小验证。
2. 一定带一句"**我上面说得不对就直接指出，别顺着我说**"——防应声虫最有效的办法。
3. **别拿"两个模型都同意"当证据**：两个都同意 ≠ 对。**只有实物算数。**
