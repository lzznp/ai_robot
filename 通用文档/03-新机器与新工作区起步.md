# 03 · 新机器 / 新工作区起步清单

> 用途：**换台电脑、或开一个新工作区**时的第一场对话，**按这份现查**，不要凭记忆开工。
> 本文件只写"**怎么查**"，不写"是什么" —— 环境口径一定会变。

---

## 第一步：先定性"哪一份才是活代码"

**踩过的坑**：盘上有多个同名目录、血缘不同（老版本 / 快照 / 在动的活代码），**认错对象＝全部白干**。

判据（按可靠性排序）：

1. **特征文件**：活代码会有某些模块/目录，老版本没有。
2. **用 hash 比对**，别只看时间戳 —— ⚠️ **时间戳在复制 / 解压 / 网盘同步后全会变**，它只能当线索，不能当证据。
3. 数量特征（文件数、总大小）只能当**辅助**。

**要做工作副本，不做原地改**：复制一份出来改，**原件保持只读**当回滚点。
（复制成本通常远小于"失去唯一对照物"的代价 —— 快照/参考代码尤其如此，它是**证据**。）

## 第二步：建回滚点（**在改任何东西之前**）

```
git init && git add -A && git commit -m baseline && git tag baseline-v0
```
没有 git 的项目：至少 `copy` 一份 `xxx.bak_<日期>`。

## 第三步：环境现查（**只查，先别装**）

把"**项目声明的版本**"和"**机器上的版本**"对齐：

| 查什么 | 怎么查 | 判据 |
|---|---|---|
| 语言工具链版本 | `go version` / `node -v` / `python -V` | 对照项目声明：`go.mod` 的 `go` 指令 / `package.json` / `requirements.txt`。**低于声明就编译不了** |
| 依赖在不在 | `node_modules` / `vendor` / 模块缓存目录是否存在 | 不在 ⇒ 要联网拉，**先确认网络** |
| 运行时不缺 | 桌面壳要 WebView2 之类 | 缺了**跑不起来**，但**编译**可能仍成功（两件事，别混） |
| 可选组件 | 打包/压缩类工具（如 NSIS、upx） | **别提前装**：先问"这个构建到底用不用它" |

### ⚠️ 网络：别用错工具

**不要用 PowerShell 的 `Invoke-WebRequest` 或 `curl.exe` 判断"有没有网"** —— 它们走 Windows **schannel**，
会因凭证问题（`SEC_E_NO_CREDENTIALS`）**假报"没网"**，让你白查半天。
**用语言自带的 TLS 栈测**（node / python / go 各自实现 TLS）——实测结果才可信。
【实测 2026-09-23：schannel 全灭，node `fetch` 200 / 149ms】

### 如果工具跑在只读沙箱里，有三个硬边界

| 现象 | 原因 | 绕法 |
|---|---|---|
| 编译器报 `pipe: Access is denied` | 沙箱禁止**管道**，而编译器必须用管道抓子工具输出 | 放宽沙箱，**或让人在沙箱外自己跑构建** |
| 写缓存目录报 `Access is denied` | 构建/模块缓存默认在**用户目录**，不在工作区内 | 把缓存路径改到工作区内（`GOCACHE` / `GOMODCACHE` / `GOPATH` 等） |
| 原生命令**重定向/管道后静默无输出**、退出码为空 | 同上，进程被掐 | **别给原生命令加重定向**；要留证据就让它自己写文件 |

**★ 补充（2026-10-03 晚实测，一条链撞了四次）**：沙箱还可能只放行**工作区里**的写入，而**越是深的子进程越容易被挡**。
特征：**我自己这一层**直接 `go build` 能过，一旦经 `wails build`（它再拉 `go`）就被拒 —— 而且报错目标会**逐个往后挪**：

| 顺序 | 报错 | 绕法 |
|---|---|---|
| 1 | `go: open …\Local\go-build\…-d: Access is denied` | 清缓存没用，见下一条 |
| 2 | `failed to initialize build cache at …\go-build: mkdir …\00: Access is denied` | `$env:GOCACHE` 指到**工作区里** |
| 3 | `go: creating work dir: mkdir …\Temp\go-build…: Access is denied` | `$env:GOTMPDIR` 指到**工作区里** |
| 4 | `open C:\…\Temp\wailsbindings.exe: Access is denied`（wails 自己写的） | `$env:TEMP`／`$env:TMP` 指到**工作区里** |

⇒ 别逐个试，**先把规律认出来**（"子进程写工作区外一律被挡"），四个环境变量一起改；编完把那几个临时目录删掉，别留在工作区里给 git 添乱。
（顺带：`go clean -cache` 之后若缓存目录变成"删不掉也建不进"，**整个删掉重建**即可恢复；ACL 此时是干净的，别往 DACL 上找原因。）

### ⚠️ 第四条硬边界：**DSH 工作区里的 exe 是「低完整性进程」⇒ WebView2/Chromium 起不来**（2026-10-03 结案）

**结论（已证）**：DSH 会给**它接管过的工作区目录**打一个 **`Low Mandatory Level`（低完整性）标签**，**子目录会继承**。于是工作区里**任何** exe 启动后都是**低完整性进程**：

- **普通 Win32 程序照跑**（实测：自编最小 GUI 探针 7 项全过）；
- **WebView2 / Chromium 必崩** —— 浏览器子进程根本创建不出来：
  `[WebView2 Error] error creating controller with 8000ffff: Catastrophic failure`。

⚠️ 标签在 **SACL** 里 ⇒ **`Get-Acl` 默认看不到**（`Get-Acl -Audit` 在特权没启用时会**静默返回空**，别据此下"没有标签"的结论）。**判它要看行为**：在那个目录里跑 `whoami /all`，看 `Mandatory Label`。

**证据（每一步都实测，可复现）**

| 实验 | 结果 |
|---|---|
| 同一 exe：工作区内 vs 外 | 内 ❌ `8000ffff`；外 ✅ |
| 进程令牌（`whoami /all`）：内 vs 外 | 内 **Low**；外 **High** |
| **反向复现**：给工作区**外**目录打 Low 标签 | 壳**立刻崩** `8000ffff` |
| **清理**：去掉工作区根目录的标签 | 壳**在工作区内起来**（探针 `probe=PASS(7/7) shell=PASS`） |
| 只给**目录**打标签（文件不打） | 里面的 exe 照样变 Low ⇒ 起作用的是**目录**标签 |
| **junction 双向**（路径内/外 × 文件实体内/外） | 跟**文件实际住的目录**走，**与路径字符串无关** |
| **SDDL 逐字节复刻**工作区 ACL 到工作区外 | 照样能跑 ⇒ **ACL 清白**（2026-10-03 终审证伪） |
| 最小 Win32 探针在工作区内 | **7/7 全过** ⇒ 不是"任何图形界面都不行" |
| `msedgewebview2.exe` 进程数 | 内 `0,0`（从没起来）；外 `0→5,6,6…` |

**怎么清（可回滚）**：用 `LABEL_SECURITY_INFORMATION`（`0x10`）＋ NULL SACL 调 `SetNamedSecurityInfo`。

- ⚠️ 用 `SACL_SECURITY_INFORMATION`（`0x8`）会得到 `rc=1314 ERROR_PRIVILEGE_NOT_HELD`（会话没有 `SeSecurityPrivilege`）；
- `icacls` **只能"设置"标签、不能"删除"**；把标签设成 `M`（Medium）**不等于没标签**（实测仍崩，只是错误码换成 `80070005`）；
- **回滚**：`icacls "<工作区>" /setintegritylevel (OI)(CI)L`；
- ⚠️ **DSH 以后可能重新打上**（切到 full-access 也没见它收回）⇒ **别把"要双击的 exe"放在工作区里**。

> **判据（可直接套用）**
> 1. 某个 GUI 程序"没反应／一闪就退" ⇒ **先把它复制到工作区外再跑**；
> 2. 想知道"坏在哪一项能力" ⇒ 跑项目里的探针：`工具\工作区GUI探针\run-probe.ps1 -Dir <目录> [-Shell <exe>]`，判据写进 `probe-report-*.json`；
> 3. **别**再花时间查显卡、运行时、代理、安全软件、路径中文、MOTW —— 这些 2026-10-03 都实测排除过；
> 4. ⚠️ **两个错误码要分清**：干净状态是 **`8000ffff`**；**有残留 `msedgewebview2.exe` 进程或脏的用户数据目录**（`%APPDATA%\<exe名>`，所有副本共用）时会伪装成 **`800700aa 资源正在使用中`**。测之前先杀进程 ＋ 清掉那个目录。

**怎么用**

- ✅ 代码、文档、数据放工作区（读、改、当参考都行）；
- ✅ 也可以在工作区里**构建**；
- ❌ **别在工作区里"双击／运行" WebView2 / Chromium 类程序**；
- ⇒ **要运行的那一份放工作区外**（本项目叫**运行位**，`build.ps1` 会自动投递；见 `README.md`）。

**顺带一个可复用的排查手法**（GUI 程序没有控制台，报错没人看得见）：

```powershell
$p = Start-Process -FilePath <exe> -WorkingDirectory <dir> -PassThru -RedirectStandardError err.txt
Start-Sleep -Seconds 14
if ($null -eq $p) { "启动这一步就失败了" } elseif ($p.HasExited) { "退出码 = $($p.ExitCode)" } else { "仍在运行 = 起来了" }
Get-Content err.txt
```

⚠️ **必须判 `$null`**：`Start-Process` 失败时 `$p` 是 `null`，而 `-not $p.HasExited` 会算成 **"活着"** ⇒ **假成功**（本项目探针的第一版就栽在这儿，2026-10-03）。

**读退出码**：Go 里 `log.Fatal` → **退出码 1**；`panic` → **退出码 2**。这一个数字就能把范围砍一半。

**诚实边界（2026-10-03 重新声明）**

- ✅ **"是低完整性标签"＝已证**（有反向复现 ＋ 清理后修复）。
- ❌ **不是 ACL**（SDDL 逐字节复刻后照样能跑）。
- ❌ **不是路径字符串 / 目录名 / 中文 / 空格**（junction 双向对照）。
- ❌ **不是"文件是拷贝来的"**（工作区内全新目录里拷一份照样失败 —— 因为标签会**继承**）。
- ❌ **不是 MOTW**（实测：内外副本带不带标记与结果无关；runtime 那几个 exe 上的 `ZoneId=3` 与本故障无关）。
- ❌ **不是显卡/GPU**（`--disable-gpu` 无效）、**不是工具沙箱的进程限制**、**不是"缺 AppContainer 组"**。
- ❌ **不是"任何图形界面程序"** —— 只有 Chromium/WebView2 这一支倒下。
- ❌ **不是安全软件**（2026-10-03 把电脑管家整个卸载后，现象不变）。
- ⚠️ **WebView2 用户数据目录的位置**：仍无定论；但它**按 exe 名字取**（`%APPDATA%\<exe名>`）⇒ 测之前务必清。

## 第四步：判断"缺什么就装什么"（**别先装一堆**）

按顺序问三句：

1. **这个构建真的需要它吗？** —— 去源码里找证据。
   例：源码 grep 不到 `import "C"` / `#cgo` ⇒ **不需要 C 编译器**；依赖是纯 Go 实现 ⇒ 同理。【实测：确实不用装 gcc 就编过了】
2. **能不能先用现成产物验证？** —— 仓库里若已有构建好的产物（`dist/`、`bin/*.exe`），
   **可以先跑它**，把"能不能跑"和"能不能编"**分开验证**，省掉一轮安装。
3. **前人写过手册的，先照手册、别自己摸** —— 现成的一例：
   DSH 浏览器助手（`dsh-browser`）→ 看同目录 [dsh浏览器助手-安装手册.md](dsh浏览器助手-安装手册.md)
   （2026-10-17 两台机装通；含**四步人工的顺序**、别写死安装根、四个实测坑）。
   ★ 那份手册里的**绝对路径全是"某台机"的值**，一律现查。

## 第五步：验证顺序（**不许假成功**）

1. **"能编" ≠ "能跑"** —— 分开验证，**别用一个的结论去写另一个的状态**。
2. **"能编"的判据**：退出码 0 **+ 产物真的存在** + 读得出构建信息
   （例：`go version -m <exe>` 能看到依赖版本与你声明的 `go.mod` 对齐）。
3. **"能跑"的判据**：**有客观探针**（进程活着 / 端口有响应 / 文件真的产生），
   不是"我看见窗口开了"。
4. ⚠️ **命令 0 秒返回、退出码为空** —— 那是**假成功**（进程根本没跑起来），
   必须查原因，**别记成"通过"**。【实测踩过：一次"编译"0.07 秒返回，实际没编】
