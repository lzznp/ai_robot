# SDK 编程模式 vs 传统编程模式 · 原理与设计思路转变

> 版本：2026-09-12 v1 ｜ 作者：小画（实施对话）｜ 面向：项目所有者（非专职程序员，Python 爱好者）
> 材料来源：本项目实测（玻璃画 `bestpic/`，SDK 0.1.2rc1）+ 另一台机器实施工程师的指导（小猎项目，SDK 0.1.5rc1）
> 目的：**先理解原理，再讨论怎么推进项目**。本文档不含施工项，纯粹讲清"换挡换在哪"。
> 阅读方式：§1~§3 是地基，§4~§5 是"怎么用"，§6~§8 是"怎么不出错"。第一次读可以只看 §1、§4、§8。

## 1. 一句话本质

| | 传统编程 | SDK 编程 |
|---|---|---|
| 你写的是 | **确定的步骤**（调用图、分支、循环，设计时就定死） | **确定的骨架 + 不确定的判断者**（在骨架的分叉点上让它选） |
| 谁决定流程 | 你，编译期就定好 | 你**定骨架**；步数与路径在**运行期**才发生 |
| 代码变少了吗 | — | **没有。变的是代码管什么**：管"围栏 / 校验 / 状态 / 证据"，不再管"判断" |

一句话记住：

> **传统编程：我写判断，机器执行。**
> **SDK 编程：我写围栏，模型判断，我验证，人拍板。**

本项目就是后者：`pipeline.py`（围栏里全是确定步骤）+ `agent_bridge.py`/`controller.py`（在分叉点问模型）+ `knobs.py`（验证器）+ `main.py`（人拍板的地方）。

## 2. 调用一次 SDK，到底发生了什么（这是最容易被误解的地方）

```python
with AgentBridge() as bridge:                 # ① 首次调用才拉起"运行时"（一个独立子进程）
    reply = bridge.ask(prompt, session_id=…)  # ② 发一句话，等它**整段跑完**
```

三个必须建立的直觉：

**① `run(prompt)` ≠ "发一次 HTTP 请求"**
它是 **"启动一个 agent 循环并等它跑完"**。这个循环内部：模型思考 → 可能调用工具 → 看结果 → 再思考 → …… → 最后给你一段话。
- 本项目多数轮次：**1 次模型请求**（因为我们把它的任务压成了"输出一段 JSON"）；
- 但这是**它自己选择只用一步**，不是架构保证——本项目实测过一次 **6 次请求**的会话（它去翻代码、跑 PowerShell 了）。
- **横向对照**：另一位工程师的项目里，一次"岗前分析"是 **8 次请求**。同一套 SDK，步数差 6 倍，差别不在代码行数，在**任务性质和配置**。

**② 它是无状态的，而且看不见你的内存**
模型不记得上一轮。你以为的"接着上次说"，实际是：运行时把历史日志重放给它（花钱、有上限），或者**你自己把关键上下文重新写进 prompt**。
→ 所以本项目的"记忆"在 `orders/*/session.json`，**不在模型里**。

**③ 运行时会落盘一份"黑匣子"**
`bestpic/.dsh_home/sessions/<hash>/<session_id>/session.jsonl`：明文，含推理、用量、结束原因、工具清单、身份。
→ **这是你唯一的调试栈**。传统编程你单步调试；这里你读这个文件。

## 3. 运行时的能力边界：它能做什么、不能做什么

**它不替你做这些（永远是你的代码）：**

| 事项 | 谁负责 | 本项目对应 |
|---|---|---|
| 决定"什么时候该问模型" | 你 | `controller.py` 的三个分叉点 |
| 把状态存取、迁移、回放 | 你 | `orders.py`（含路径改写） |
| 校验模型说的话是否合法 | 你 | `knobs.validate_knobs` / `validate_local_ops` |
| 真正干活（算图、存文件） | 你 | `image_lib/pipeline.py`（纯函数、无随机） |
| 让用户看见过程、让人拍板 | 你 | `main.py`（回执/过程展开/反馈） |

**它确实替你做了这些（你只管用，别自己造）：**

| 事项 | 说明 |
|---|---|
| 拉起并管理运行时进程 | 首次调用慢（本项目 10~60s）就是这么来的 |
| 多轮 agent 循环 | 你不写循环，它自己走；你只给一次 prompt |
| 会话日志落盘 | 免费得到可追溯的"黑匣子" |
| 用量统计 | `assistant/message.data.usage`（input / cacheRead / output / reasoning / total） |
| 结束原因判定 | `RunResult.finish_reason`（如 `completed` / `max-tokens`） |
| 上下文重放（按 session_id 续聊） | 代价是钱和上下文长度 |

**它的默认值不是你要的（重要）：**
profile `sdk-minimal` 在我们版本里**仍然带着 `pwsh` 和 `str_replace_editor`**，system 位是 DSH 默认身份 `"You are a helpful software engineer assistant."`。
→ 教训：**"能用"不等于"按你的意图在跑"。身份和工具面属于"配置层"，要主动设置，不能指望默认。**

## 4. 你实际能用的三根"操纵杆"（拉起来之后，怎么更好地利用它）

把 SDK 想成"你雇了一个很能干但看不见你屏幕、也不记得上次的顾问"。你对他只有三根杆：

### 杆 1：prompt —— 任务合约（不是"聊天"）
- 里面必须包含：**它是谁（角色）/ 手上有什么（可用参数清单）/ 现在什么情况（状态与数字）/ 要它输出什么形状（JSON 契约）**
- 本项目的 prompt 由 `controller.py` 拼装：规则手册 + 旋钮清单 + 能力现状 + 上一版报告（含指标数字）+ 用户反馈
- **关键认知**：prompt 不是源代码，是**每次运行都要重新交付的合同**。你改了业务状态却不改 prompt，等于没告诉它

### 杆 2：配置 —— 身份 / 工具 / 视野 / 预算（最被忽视、收益最大）
| 配置 | 决定什么 | 本项目现状 |
|---|---|---|
| `profile` | 它**是谁**、能碰什么工具 | ⚠️ 未定制（通用软件工程师 + pwsh + 文件编辑器） |
| `cwd` | 它**看得见**哪个目录 | ⚠️ 指向 `assets/`（曾出现过指向项目根的会话） |
| `max_tokens` | 一次能写多长（截断风险） | 8192，已实测被打满过 2 次 |
| `session_id` | 是否续聊、上下文多长 | = 订单号 |
| `dsh_home` | 日志与身份档落哪儿 | 项目内 `.dsh_home`（隔离，不污染 `~/.dsh`） |

**这一根杆的杠杆率最高**：身份错了（通用编码助手）→ 它更爱"动手探索"；工具开着 → 它真的会去跑命令（本项实测被调用过 1 次，烧掉 30k token）。

### 杆 3：校验与围栏 —— 让它的话变成可执行的指令
模型输出是**建议**，不是**命令**。中间必须有你的校验器：
- 本项目：`_extract_json`（抠 JSON）→ `validate_knobs`/`validate_local_ops`（白名单 + 范围）→ 不合法的**整轮作废**
- 心法：**能被绕过的约束不要只写在提示词里**（提示词是引导，校验器是法律；更硬的约束应放在配置层）

## 5. 两种用法：先选对形态，再写代码（选错了又贵又不可控）

| | **形态 A：受校验的应答器** | **形态 B：真 agent** |
|---|---|---|
| 它做什么 | 收到状态 → 输出一小段 JSON → 你的代码执行 | 自己规划 → 调工具 → 看结果 → 再规划 |
| 步数 | 通常 1 次请求 | 几步到几十步（实测过 6 次 / 8 次） |
| 成本 | 低且可预测（本项目 3~5k token/轮） | 高且不可预测（实测一次 30k） |
| 可控性 | 高，**能逐字节复现** | 低，同输入可能不同路径 |
| 适合 | **翻译/选参数/判断方向**；有确定性执行层 | **信息要去翻找、天然的探索型任务** |
| 本项目 | ✅ 主链路（旋钮、九宫格、区域） | ❌ 不用（也不需要） |

**本项目选 A 是对的，别自卑**：玻璃画的本质是"确定性数学 + 少量审美判断"，A 形态既便宜又保住了**逐字节可复现**这个最硬资产。

**什么时候才升级到 B**：任务里出现"得先去哪儿找资料/看几个文件才知道怎么做"这种**探索性**成分时。判断口诀：

> **确定的活写代码，判断的活问模型；如果"找什么"本身都不确定，才需要 B。**

## 6. 7 个心智换挡（对照你原来的编程习惯）

| # | 你原来的默认 | SDK 编程的默认 | 本项目里的样子 |
|---|---|---|---|
| 1 | 控制流设计时确定 | **运行期才知道走几步** | `run()` 是循环；一次会话实测 1~6 次请求 |
| 2 | 类型签名 + 编译期检查 | **自然语言契约 + 运行期校验** | `validate_knobs` 就是"手写的编译器" |
| 3 | 状态在变量/内存里 | **状态必须显式落盘** | `session.json`（含 `local_ops`、`last_report`）；线程里还不能碰 UI 的 session_state |
| 4 | 出错了抛异常、有栈 | **最危险的是"静默失败"** | 三种都踩过：参数静默归零 / 越权静默发生 / 输出静默截断 |
| 5 | 断点单步调试 | **读证据 + 重放** | 读 `session.jsonl`；"同参数 → 逐字节一致"是回归断言 |
| 6 | 成本≈CPU 时间 | **每次调用真花钱，上下文越长越贵** | 把要给模型的东西压成**数字和短 JSON**，而不是丢图给它看 |
| 7 | 我写什么它就能做什么 | **"它是谁 + 有什么工具 + 在哪儿"决定行为** | 身份/工具面未定制 → 出现过它去翻代码 |

## 7. 可移植的六条纪律

1. **资产 / 壳分离**：结构化判断结果 = 资产（能被重新计算）；页面、预览图 = 壳（随时可重画）。
   判据：明天把所有代码重写，这东西还认得出来吗？
2. **边界放在运行时**，不放在提示词里；但关工具要看任务——不需要就该关，需要就"限权 + 留痕 + 闸门"。
3. **状态属于系统，不属于某次回复**：参数/区域/进度要么进订单状态、要么进日志。（本项目旋钮"静默归零"就是违反这条。）
4. **"静默失败"是最危险的失败**：凡"成功"必须是**你验过的**，不是**它说的**（产物要真的存在、能被打开）。
5. **证据 > 结论**：报数字要带来源与口径；把"推断"和"实锤"分开写。
6. **不依赖运行时内部实现**（日志格式、事件结构会随版本变）：资产不要和运行时格式耦合。
   → 也是为什么 `dsh_home` 要项目内隔离、订单归档要能脱离 SDK 独立读懂。

## 8. 你怎么给要求才不容易错（回答你"担心给错要求"）

**你不需要懂实现，但需要提供三类信息。** 只要这三类清楚，剩下的歧义我会来问，而不是猜：

| 类型 | 例子 | 缺了会怎样 |
|---|---|---|
| **要什么效果**（可观察） | "脸上那块别那么黑""背景要干净，别有小灰点" | 我只能猜，容易做偏 |
| **在哪里 / 哪个范围** | "左上角""眼睛那一圈""整张都要" | 位置错 → 效果对但位置错，最亏 |
| **什么算好 / 什么不能接受** | "宁可淡一点也别糊""不能出现方格印子" | 无法判断收敛，来回改 |

**反过来，这些你不需要给**：用什么算法、几个参数、改哪个文件、要不要加线程——**这些是我的活**。

**降低"给错要求"的三个机制（我们已经在用，可以继续加强）**：
1. **先出小样再定**：任何不确定的想法，先做"能看见的最小一步"（比如这次的画布实验页），你看了再决定要不要推进——比纸上讨论准得多
2. **让系统自己报数字**：页面显示"暗部 21.4% → 15.2%"这类实测，你就能一眼看出是不是你要的，不用凭感觉
3. **我不确定就说不确定 + 给选项**：我会把"推断"和"实锤"分开，并告诉你每条路线的代价，你只做取舍

**还有一条心法**：要求可以**分次给**。SDK 模式下"先要个能跑的版本，再逐步加限制"比"一次说全"更省事——因为每一轮都有产物可看、有数字可核对。

## 9. 新的设计思路（下次提需求时可以直接套这个模板）

**① 先判断这件事属于哪一类**

| 类型 | 处理方式 | 例子 |
|---|---|---|
| 纯确定 | 直接写代码，不问模型 | 灰度换算、仿色、尺寸换算、文件归档 |
| 判断（人话→参数） | 问模型，**只让它回 JSON** | "背景白一点" → 旋钮取值 |
| 探索（要先找才知道） | 才需要真 agent（本项目暂不需要） | "从这些候选人里找出最合适的" |
| 审美/看图 | 视觉模型当"监工"，只报观察不改流程 | "有没有格子印子/背景够不够白"（本项目未做） |

**② 再问这 8 个问题**（新功能开工自查）
1. 这一步里"哪些是确定的"？（确定的部分必须是纯函数 + 可复现）
2. 要模型判断什么？它的输出形状（JSON 契约）是什么？
3. 它需要什么信息才能判断？（状态 + 数字，尽量短）
4. 输出非法怎么办？（拒绝 + 明确报错；哪种失败可以重试）
5. 这个状态存哪？（订单/日志；能不能重放）
6. 失败怎么让我看见？（**不许静默**）
7. 它需要工具吗？身份对吗？视野（cwd）开对了吗？
8. 成本多少？（几次请求、多少 token、能不能缓存）

**③ 最后问一句"边界"**：这件事里，谁能改什么？
（本项目现状：模型只能建议参数；代码只能执行确定性算子；**唯有你能拍板"就这样上机"**。）
