**websocket_server.py (行 74-82)**
```python
async def start(self):
    server_config = self.config["server"]
    host = server_config.get("ip", "0.0.0.0")
    port = int(server_config.get("port", 8000))

    async with websockets.serve(
        self._handle_connection, host, port, process_request=self._http_response

```

### 1.2 当前配置参数

websockets.serve() 调用中**未设置以下关键参数**：

| 参数 | 当前值 | websockets 14.x 默认值 |
|------|--------|----------------------|
| `ping_interval` | **未设置** | 20 秒 |
| `ping_timeout` | **未设置** | 20 秒 |
| `close_timeout` | **未设置** | 10 秒 |
| `max_size` | **未设置** | 1 MB |

这意味着服务器使用了 **websockets 库的默认行为**：每 20 秒发送一次 WebSocket 协议级 ping 帧，若 20 秒内未收到 pong 帧，则认为连接已断开并关闭。

### 1.3 影响分析

  **需要关注** — 当 ESP32 客户端无法正确响应 WebSocket 协议级 ping 时，连接会在约 20-40 秒内被关闭。加上重试和网络延迟，表现为约 1 分钟断开。

```
时间线（ping_interval=20s, ping_timeout=20s）：
T=0     → 连接建立
T=20s   → 服务器发送 WebSocket Ping 帧
T=20-40s→ 等待客户端 Pong 响应
T=40s   → 未收到 Pong → 服务器关闭连接
```

**pingMessageHandler.py 完整代码 (行 1-46)：**

```python
class PingMessageHandler(TextMessageHandler):
    """Ping消息处理器，用于保持WebSocket连接"""

    @property
    def message_type(self) -> TextMessageType:
        return TextMessageType.PING

    async def handle(self, conn, msg_json: Dict[str, Any]) -> None:
        # 检查是否启用了WebSocket心跳功能
        enable_websocket_ping = conn.config.get("enable_websocket_ping", False)
        if not enable_websocket_ping:
            conn.logger.debug(f"WebSocket心跳功能未启用，忽略PING消息")
            return

        try:
            conn.logger.debug(f"收到PING消息，发送PONG响应")
            conn.last_activity_time = time.time() * 1000  # 更新活动时间戳
            # 构造PONG响应消息
            pong_message = {
                "type": "pong",
                "timestamp": time.strftime("%Y-%m-%d %H:%M:%S", time.localtime()),
            }
            await conn.websocket.send(json.dumps(pong_message))
        except Exception as e:
            conn.logger.error(f"处理PING消息时发生错误: {e}")
```

### 2.4 关键配置项

**config.yaml (行 75)：**
```yaml
# 是否启用WebSocket心跳保活机制
enable_websocket_ping: false
```

⚠️ **存在问题** — 应用层 Ping/Pong 功能**默认关闭**！即使 ESP32 客户端发送了 `{"type": "ping"}` 消息，服务器也会直接忽略，不会回复 Pong。

### 3.2 会话超时（两层关闭机制）

系统采用**两层关闭机制**来管理连接超时：

#### 第一层：`close_connection_no_voice_time`（无语音活动超时）

| 文件 | 行号 | 内容 |
|------|------|------|
| `core/handle/receiveAudioHandle.py` | 234-258 | `no_voice_close_connect()` |
| `config.yaml` | 61 | `close_connection_no_voice_time: 1800` |

```python
async def no_voice_close_connect(conn, have_voice):
    if have_voice:
        conn.last_activity_time = time.time() * 1000  # 有语音时更新时间戳
        return
    if conn.last_activity_time > 0.0:
        no_voice_time = time.time() * 1000 - conn.last_activity_time
        close_connection_no_voice_time = int(
            conn.config.get("close_connection_no_voice_time", 120)  # 默认 120 秒
        )
        if not conn.close_after_chat and no_voice_time > 1000 * close_connection_no_voice_time:
            conn.close_after_chat = True
            # ... 触发结束对话流程
```

  **当前配置**: `close_connection_no_voice_time: 1800` → 30 分钟无语音活动才关闭
  **默认值**: 120 秒（2 分钟）

#### 第二层：`timeout_seconds`（加强超时）

| 文件 | 行号 | 内容 |
|------|------|------|
| `core/connection.py` | 194-197 | timeout_seconds 计算 |
| `core/connection.py` | 414 | 启动超时检查任务 |
| `core/connection.py` | 1782-1811 | `_check_timeout()` 实现 |

```python
# connection.py 行 194-197
self.timeout_seconds = (
    int(self.config.get("close_connection_no_voice_time", 120)) + 60
)  # 在原来第一道关闭的基础上加60秒，进行二道关闭
self.timeout_task = None
```

```python
# connection.py 行 1782-1811
async def _check_timeout(self):
    """检查连接超时"""
    try:
        while not self.stop_event.is_set():
            last_activity_time = self.last_activity_time
            if self.need_bind:
                last_activity_time = self.first_activity_time
            if last_activity_time > 0.0:
                current_time = time.time() * 1000
                if current_time - last_activity_time > self.timeout_seconds * 1000:
                    if not self.stop_event.is_set():
                        self.logger.bind(tag=TAG).info("连接超时，准备关闭")
                        self.stop_event.set()
                        try:
                            await self.close(self.websocket)
                        except Exception as close_error:
                            ...
                    break
            await asyncio.sleep(10)  # 每10秒检查一次
    except Exception as e:
        ...
```

  **当前计算**: `1800 + 60 = 1860` 秒 = **31 分钟**
  **默认计算**: `120 + 60 = 180` 秒 = **3 分钟**

```python
async def register(self, device_id, websocket, metadata=None):
    async with self._lock:
        self._connections[device_id] = websocket
        self._device_info[device_id] = {
            "online": True,
            "last_seen": datetime.now().isoformat(),
```

### 4.2 连接时效性检查

  **存在问题** — `DeviceManager` 虽然记录了 `last_seen`，**但没有任何定时任务去检查连接是否超时**。连接的"保活"完全依赖上层 `ConnectionHandler` 的 `_check_timeout()` 方法。

`update_heartbeat` 方法存在但**没有地方调用它**：

```python
# device_manager.py 行 97-99
async def update_heartbeat(self, device_id: str):
    """更新设备心跳时间"""
    if device_id in self._device_info:
        self._device_info[device_id]["last_seen"] = datetime.now().isoformat()
```

📝 **参考此逻辑** — 这个 `update_heartbeat` 方法是为心跳功能预留的，但未被集成到任何消息处理流程中。如果启用心跳，需要在这里补充调用。

### 4.3 断开清理逻辑

| 文件 | 行号 | 内容 |
|------|------|------|
| `core/websocket_server.py` | 154-171 | `_handle_connection()` 的 finally 块 |
| `core/connection.py` | 1626-1715 | `close()` 资源清理 |

**websocket_server.py (行 150-171)：**
```python
try:
    await handler.handle_connection(websocket)
except Exception as e:
    ...
finally:
    # 注销设备
    if handler.device_id:
        await self.device_manager.unregister(handler.device_id)
    # 强制关闭连接
    try:
        await websocket.close()
    except Exception as close_error:
        ...
```

  **清理逻辑存在但有问题**：当 WebSocket 库因协议层 ping/pong 超时而**自行关闭**连接时，`async for message` 循环收到 `ConnectionClosed` 异常并退出，随后 finally 块会执行清理。但如果连接被 WebSocket 库强制关闭而非正常退出，`_handle_connection()` 的 try 块中的 `handler.handle_connection()` 会在 `await self.websocket` 处抛出异常，导致部分清理路径走不到。

## 6. 核心问题分析：1 分钟断连根因

### 6.1 根因总结

**断连原因：websockets 14.x 库的默认 Ping/Pong 机制。**

服务器启动 `websockets.serve()` 时**未设置 `ping_interval`**，使用了库的默认值 20 秒。当 ESP32 客户端不响应 WebSocket 协议层的 Ping 帧时，`ping_timeout`（默认 20 秒）到期导致连接被关闭。

### 6.2 不是这些原因

| 排除项 | 原因 |
|--------|------|
| ❌ `close_connection_no_voice_time` | 当前配置为 1800 秒（30 分钟），不是 1 分钟 |
| ❌ `_check_timeout()` 应用层超时 | 超时时间为 1860 秒（31 分钟），不是 1 分钟 |
| ❌ 应用层 PingMessageHandler | `enable_websocket_ping: false`，功能未启用，但即使启用也不影响 WebSocket 协议层的行为 |
| ❌ Nginx 反向代理超时 | 如果用户使用反向代理，通常的 proxy_read_timeout 默认是 60 秒，这可能是另一个原因，但代码中无此配置 |

### 6.3 `close_connection_no_voice_time: 1800` 的注释不一致

  **需要关注** — config.yaml 第 60-61 行：

```yaml
# 没有语音输入多久后断开连接(秒)，默认2分钟，即120秒
close_connection_no_voice_time: 1800
```

注释说"默认 2 分钟 / 120 秒"，但实际配置值是 **1800 秒（30 分钟）**。注释和实际值严重不一致。

## 7. 修复方案与影响评估

### 方案 A：禁用 WebSocket 协议层 Ping（推荐）

  "可以直接修改"

**修改文件**：`core/websocket_server.py` 第 79-81 行

**修改内容**：在 `websockets.serve()` 中显式传入 `ping_interval=None` 和 `close_timeout=None`

```python
# 修改前
async with websockets.serve(
    self._handle_connection, host, port, process_request=self._http_response
):

# 修改后
async with websockets.serve(
    self._handle_connection, host, port,
    process_request=self._http_response,
    ping_interval=None,      # 禁用协议层 ping
    ping_timeout=None,        # 禁用协议层 pong 超时
    close_timeout=10,         # 保留关闭超时（安全）
):
```

**影响评估**：
- ✅ 解决 1 分钟断连问题
- ✅ 仅影响 WebSocket 协议层，不影响应用层逻辑
- ✅ 无安全风险（应用层 `_check_timeout` 仍会按 31 分钟超时断开）
- ✅ 改动量最小（仅 3 行）
- ⚠️ 连接将保持到应用层超时（31 分钟）或客户端主动断开
- ⚠️ 如果需要在无活动时更快断开，可配合调整 `close_connection_no_voice_time` 配置

### 方案 B：启用应用层 Ping/Pong 并禁用协议层 Ping

  **参考此逻辑** +   "可以直接修改"

**需要修改的文件**：

1. `config.yaml` 行 75：`enable_websocket_ping: true`
2. `core/websocket_server.py` 行 79-81：添加 `ping_interval=None`（同方案 A）
3. ESP32 客户端需要定期发送 `{"type": "ping"}` 消息（约每 30-50 秒一次）

**修改内容（config.yaml）**：
```yaml
# 是否启用WebSocket心跳保活机制
enable_websocket_ping: true
```

**影响评估**：
- ✅ 更规范的双向心跳机制
- ✅ 服务器回复 Pong 时会更新 `last_activity_time`，防止应用层超时
- ❌ 需要修改 ESP32 客户端代码定时发送 ping
- ❌ 改动量较大

### 方案 C：仅调整 `close_connection_no_voice_time`

  **参考此逻辑**

如果用户实际上希望连接在无活动一段时间后断开（而非永久保持），可以调整配置。

**修改文件**：`config.yaml` 第 61 行

```yaml
# 没有语音输入多久后断开连接(秒)
close_connection_no_voice_time: 120  # 2 分钟无语音后断开
```

但此方案**不解决根本问题**——协议层 ping/pong 超时仍然会导致 1 分钟断连。

### 7.1 推荐方案：方案 A

**修改一处代码，即可解决 1 分钟断连问题。** 无需修改配置文件，无需修改 ESP32 客户端。

```diff
# core/websocket_server.py
 async with websockets.serve(
-    self._handle_connection, host, port, process_request=self._http_response
+    self._handle_connection, host, port,
+    process_request=self._http_response,
+    ping_interval=None,
+    ping_timeout=None,
+    close_timeout=10,
 ):
```

### 7.2 如果还希望保留连接保活测量

如果希望在禁用协议层 ping 后仍然能检测"死连接"，可以启用应用层心跳（方案 B），让 ESP32 客户端定期发送 `{"type": "ping"}`。服务器端的 `PingMessageHandler` 已经实现了完整逻辑，只需将 `enable_websocket_ping` 设为 `true` 即可。
