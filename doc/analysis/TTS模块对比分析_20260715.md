# TTS 模块对比分析报告

> **日期**: 2026-07-15  
> **项目**: xiaozhi-server（当前工作目录） vs xiaozhi-server-old（原始备份）  
> **范围**: 8 个指定文件 / 目录  

---

## 总体结论

当前版本（`xiaozhi-server/`）相对于原始版本（`xiaozhi-server-old/`）新增了 **多角色调度系统**（World / Character / LLMAdapter）和 **场景调度系统**（SceneDispatcher），但 **TTS 核心链路（音频流生成 → 编码 → 队列 → 推送）未发生任何实质性修改**。如果出现 TTS 不工作的问题，问题根源在于新引入的**优先级路由导致原有 LLM 流程未被命中**，而非 TTS 底层代码本身。

### TTS 链路对比（`chat()` 方法）

📝 **参考此逻辑**：`chat()` 方法中所有 `self.tts.tts_text_queue.put()` 调用在两侧完全一致：

```
chat(query)
↓
生成 sentence_id → self.sentence_id = current_sentence_id
↓
往 self.tts.tts_text_queue 中放入 TTSMessageDTO
  ├─ FIRST（第一句）[行 1157 / 919]
  ├─ MIDDLE（流式中间内容）[行 1272,1295,1305 / 1034,1057,1067]
  ├─ MIDDLE（工具调用时）[行 1370 / 1132]
  ├─ LAST（正常结束）[行 1314,1385 / 1076,1147]
  └─ LAST（非流式兜底）[行 1464 / 1225]
↓
tts_text_priority_thread 消费 TTSMessageDTO → 调用 to_tts_stream() / to_tts()
↓
opus 编码后推入 tts_audio_queue
↓
audio_play_priority_thread 消费 → sendAudioMessage()
↓
WebSocket 发送到设备
```

> `tts_text_queue.put()` 调用次数完全相同（11 次），没有任何新增/删除/修改。

### 可能影响 TTS 的关键差异

- **新增自连接逻辑**（约 602-609 行）：`Application::Start()` 末尾新增了自动 `ToggleChatState()` 调用，在设备就绪后自动触发一轮聊天。这会触发 `startToChat` → 可能进入 World/SceneDispatcher，**如果配置了 World 但没有正确回退到原有流程，TTS 可能被 World 短路**。

#### 2.3 `startToChat()` 重构（144 行起）

原版：

```python
async def startToChat(conn, text):
    # 解析说话人JSON
    # 检查绑定、输出限制
    # handle_user_intent()
    # → 如果未处理：走原有 LLM 流程
    await send_stt_message(conn, actual_text)
    conn.client_abort = False
    conn.executor.submit(conn.chat, actual_text)     # ← 直接调 chat()
```

当前版：

```python
async def startToChat(conn, text):
    # ...前置检查与原来一致...

    # ★ 优先级 1：SceneDispatcher 场景调度
    if hasattr(conn, 'scene_dispatcher') and conn.scene_dispatcher:
        result = await conn.process_with_scene(actual_text)
        if result.get("actions") or result.get("response"):
            return    # ← SceneDispatcher 处理后直接返回，不走 LLM

    # ★ 优先级 2：World 多角色调度
    if hasattr(conn, 'world') and conn.world:
        results = conn.world.process(actual_text)
        if results:
            await _dispatch_world_results(conn, results)
            return    # ← World 处理后直接返回，不走 LLM

    # ★ 优先级 3：原有逻辑（走 LLM 流程）
    await send_stt_message(conn, actual_text)
    conn.client_abort = False
    conn.executor.submit(conn.chat, actual_text)
```

 **可能导致 TTS 不工作的关键差异**：当前版本中，`startToChat` 新增了 **3 级优先级路由**：
1. SceneDispatcher — 如果配置了场景调度，由它处理并直接返回
2. World — 如果配置了多角色调度，由 World 处理并分发到各设备，**走特殊的 TTS 路径**
3. 原有 LLM 流程 — 仅在前两者都未命中时才执行

如果 SceneDispatcher 或 World 被启用但配置不正确、或返回了空结果而没有正确回退，**原有 LLM 流程（含正常 TTS 链路）将被跳过**。

### 2.4 World 流程中的 TTS 调用（`_dispatch_world_results` 内）

```python
async def _dispatch_world_results(conn, results):
    for result in results:
        role_name, response_text = result.split(": ", 1)
        # ...查找目标设备连接...
        device_conn.tts.tts_one_sentence(device_conn, ContentType.TEXT,
                                          content_detail=response_text)
```

📝 **TTS 路径变化**：World 流程直接调用 `tts_one_sentence()`，该方法将文本按标点拆分后放入 `tts_text_queue`，**绕过了 `chat()` 方法中的 LLM 流式处理和分句逻辑**。这种调用方式：
- 能生成 TTS 音频并推送到设备
- 但**没有经过 LLM 流式迭代器**，速度取决于角色 LLM 的响应速度
- 适用于单一响应文本的直接朗读

## 6. `core/llm_adapter.py` — 新增文件

### 文件状态

| 文件名 | 原版 (old) | 当前版 (current) |
|--------|-----------|-----------------|
| `llm_adapter.py` | ❌ 不存在 | ✅ 新增 |

### 功能说明

`LLMAdapter` 是一个适配器，将小智原版的 LLM 接口适配为 `Character` 期望的接口形式：

```
Character 期望:  llm_client(messages: List[Dict]) -> str
小智 LLM 接口:   llm.response(session_id, messages) -> 流式迭代器
```

核心代码：

```python
class LLMAdapter:
    def __init__(self, llm_instance, session_id: str = None):
        self.llm = llm_instance

    def __call__(self, messages: List[Dict]) -> str:
        full_response = ""
        if hasattr(self.llm, 'response'):
            responses = self.llm.response(self.session_id, messages)
            for chunk in responses:   # 收集流式响应为完整文本
                if isinstance(chunk, str): full_response += chunk
                ...
        return full_response.strip()
```

### TTS 链路中的角色

这个类在 `World` 模块中使用，当用户输入被路由到 World（而非原有 chat()）时：

```
用户输入 → startToChat() → World.process() → Character.say()
    → LLMAdapter.__call__(messages)  ← 替代原有 llm.response()
    → 返回完整文本
    → _dispatch_world_results() → tts_one_sentence() → TTS
```

与原有 LLM 链路的差异：

| 特性 | 原有 `chat()` 方法 | World + LLMAdapter |
|------|-------------------|-------------------|
| LLM 调用方式 | 流式迭代 + 实时分句 | 收集完整响应后一次性分句 |
| TTS 触发时机 | 流式过程中逐句触发 | 完整文本后调用 `tts_one_sentence()` |
| TTS 实时性 | 高（边生成边朗读） | 中等（等待完整响应） |
| 分句逻辑 | `_get_segment_text()` | `tts_one_sentence()` 内部的 `re.split()` |

## 7. `core/world.py` — 新增文件

### 文件状态

| 文件名 | 原版 (old) | 当前版 (current) |
|--------|-----------|-----------------|
| `world.py` | ❌ 不存在 | ✅ 新增 |

### TTS 链路中的交互

World 是**多角色调度器**，`receiveAudioHandle` 中调用它：

```
用户输入 → startToChat()
  ├─ 优先级 1: SceneDispatcher（若有）
  ├─ 优先级 2: World（若有）           ← World 在此拦截
  │   ├─ detect_target() → 识别目标角色
  │   ├─ Character.say() → LLMAdapter → LLM
  │   └─ 返回 ["角色名: 台词", ...]
  │
  └─ _dispatch_world_results()  ← 分发 TTS
      ├─ send_stt_message(device_conn, response_text)
      └─ device_conn.tts.tts_one_sentence(...)  ← 绕过 chat()，直接 TTS
```

World 的 `process()` 将文本交给指定 Character 处理，Character 调用 LLMAdapter（而非原有 LLM 流式接口）。**World 流程完全绕过了 `chat()` 方法**，使用独立的 TTS 触发路径。

### 可能影响 TTS 的问题

- **LLMAdapter 与原有 LLM 的接口兼容性**：若 LLMAdapter 调用失败或返回空，`_dispatch_world_results` 只会记录日志，不触发任何 TTS
- **设备 ID 映射错误**：`_dispatch_world_results()` 需要正确映射角色名到设备 ID，若映射失败（`_get_device_id_for_role` 返回 None），TTS 消息将被丢弃
- **设备连接查找失败**：`_get_device_connection()` 通过多个方式查找设备连接，但依赖于 `device_manager` 的存在

## 附录：TTS 链路流程图

### 原有流程（old）

```
ASR完成 → startToChat()
  → send_stt_message()            ← 通知客户端"开始说话"
  → chat(query)                    ← LLM 流式交互
    → llm.response()              ← 流式迭代
    → tts_text_queue.put(MIDDLE)  ← 逐句送入 TTS 队列
    → tts_text_queue.put(LAST)    ← 最后一句
  → tts_text_priority_thread()    ← 消费 TTS 文本
    → to_tts_stream()             ← TTS 服务生成音频
    → handle_opus() → tts_audio_queue
  → audio_play_priority_thread()  ← 消费音频
    → sendAudioMessage()          ← 发送到 WebSocket
```

### 新流程（current）— 当 World 启用时

```
ASR完成 → startToChat()
  → 检查 SceneDispatcher (优先级 1)
  → 检查 World (优先级 2)
    ├─ World.detect_target()      ← 识别目标角色
    ├─ Character.say()
    │   ├─ build_messages()       ← 构建角色专属 prompt
    │   └─ LLMAdapter()           ← 收集完整响应
    └─ _dispatch_world_results()
      ├─ send_stt_message()       ← 通知客户端
      └─ tts_one_sentence()       ← 按标点分割后送入 TTS
  → tts_text_priority_thread()    ← 消费 TTS 文本（与旧版相同）
  → audio_play_priority_thread()  ← 消费音频（与旧版相同）
```

### 新流程（current）— 当 World 未启用时

```
ASR完成 → startToChat()
  → 检查 SceneDispatcher → 跳过（未配置）
  → 检查 World → 跳过（未配置）
  → 原有 chat() 流程             ← 与旧版完全一致
```

> **只有在 World / SceneDispatcher 被配置且启用时**，TTS 链路才会走不同路径。如果未配置这两个系统，TTS 行为与旧版完全相同。
