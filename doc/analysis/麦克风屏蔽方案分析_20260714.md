## 1. 音频服务类 (AudioService) 接口分析

### 1.1 AudioService 类概览

文件：`esp32-firmware/main/audio/audio_service.h`

该类没有直接名为 `EnableMic()`、`SetMicGain()`、`IsMicEnabled()` 的方法。麦克风的控制通过以下层次实现：

```
Application → AudioService → AudioCodec (硬件抽象)
              ↓
        EnableVoiceProcessing()  — 控制音频处理器（VAD/AFE）的启停
        EnableWakeWordDetection() — 控制唤醒词检测的启停
        ReadAudioData()           — 内部通过 codec_->EnableInput() 控制
```

## 2. 音频服务初始化流程

### 2.1 启动链路

```
main.cc:app_main()
  → Application::Start()              [application.cc:351]
    → board.GetAudioCodec()           [application.cc:362]  ← 获取硬件编解码器
    → audio_service_.Initialize(codec) [application.cc:363]
    → audio_service_.Start()           [application.cc:364]
    → 设置回调 → 启动主循环 → 启动网络 → 检查版本 → 启动协议
```

### 2.2 `AudioService::Initialize()` 执行内容

文件：`audio/audio_service.cc:32-74`

```cpp
void AudioService::Initialize(AudioCodec* codec) {
    codec_ = codec;
    codec_->Start();    // ← —— 关键：此处启动编解码器硬件！

    // 初始化 Opus 编解码器
    opus_decoder_ = ...;
    opus_encoder_ = ...;

    // 创建音频处理器（AFE 或 NoAudioProcessor）
    audio_processor_ = ...;

    // 设置处理器输出回调 → 数据送入编码队列
    audio_processor_->OnOutput([this](std::vector<int16_t>&& data) { ... });

    // 设置 VAD 状态变更回调
    audio_processor_->OnVadStateChange([this](bool speaking) { ... });

    // 创建音频电源管理定时器
    esp_timer_create(&audio_power_timer_args, &audio_power_timer_);
}
```

### 2.3 初始化时麦克风是否开启？

**初始化阶段：麦克风没有明确打开**。`Initialize()` 中只调用了 `codec_->Start()`，其效果因编解码器而异：

- **ES8311** (`es8311_audio_codec.cc`)：`Start()` 继承自 `AudioCodec`，**基类中的 Start() 是一个空虚拟方法**，不做任何事。真正的硬件初始化在构造函数中完成（I2S 通道创建 + ES8311 配置）。
- `codec_mode = ESP_CODEC_DEV_WORK_MODE_BOTH` — ES8311 配置为 DAC+ADC 双工模式，但硬件设备句柄 `dev_` 的创建是**延迟的**，由 `UpdateDeviceState()` 在首次 `EnableInput()` 或 `EnableOutput()` 时触发。

 **初始化后默认麦克风不开启**，需要在后续状态切换中通过 `EnableInput()` 或 `EnableVoiceProcessing()` 显式打开。

### 2.4 音频电源管理（自动关闭麦克风）

文件：`audio/audio_service.cc:637-650`

```cpp
void AudioService::CheckAndUpdateAudioPowerState() {
    auto now = std::chrono::steady_clock::now();
    auto input_elapsed = std::chrono::duration_cast<std::chrono::milliseconds>(now - last_input_time_).count();
    // 如果 15 秒没有输入，自动关闭麦克风
    if (input_elapsed > AUDIO_POWER_TIMEOUT_MS && codec_->input_enabled()) {
        codec_->EnableInput(false);   // ← 自动关闭麦克风
    }
    // 如果 15 秒没有输出，自动关闭扬声器
    if (output_elapsed > AUDIO_POWER_TIMEOUT_MS && codec_->output_enabled()) {
        codec_->EnableOutput(false);
    }
    // 如果输入和输出都关闭了，停止定时器
    if (!codec_->input_enabled() && !codec_->output_enabled()) {
        esp_timer_stop(audio_power_timer_);
    }
}
```

- `AUDIO_POWER_TIMEOUT_MS = 15000`（15 秒无活动后自动关闭）
- 但在 `ReadAudioData()` 中，如果发现未启用输入，**会自动重新打开**（见 1.2-⑥）

### 3.4 `SetDeviceState()` 各状态对麦克风的完整操作

文件：`application.cc:732-789`

| 状态 | EnableVoiceProcessing | EnableWakeWordDetection | 麦克风实际状态 |
|------|----------------------|------------------------|----------------|
| `kDeviceStateIdle` | **关闭** 🔴 | **开启** 🟢 | **仅唤醒词使用**（采集少量数据喂给唤醒词模型） |
| `kDeviceStateListening` | **开启** 🟢 | **关闭** 🔴 | **全开**（采集数据 → VAD → 编码 → 发送服务器） |
| `kDeviceStateSpeaking` | **关闭**（非实时模式）🔴 | **AFE唤醒词时可开启** 🟡 | **关闭或仅唤醒词采集** |
| `kDeviceStateConnecting` | 不变 | 不变 | 保持之前状态 |
| `kDeviceStateStarting` | 不变 | 不变 | 初始状态，无麦克风活动 |

 **关键时序**：在 `Application::Start()` 末尾（第 592 行）调用 `SetDeviceState(kDeviceStateIdle)`，此时：

```cpp
case kDeviceStateIdle:
    audio_service_.EnableVoiceProcessing(false);    // 关闭语音处理
    audio_service_.EnableWakeWordDetection(true);   // 开启唤醒词检测
```

→ **空闲时麦克风仅用于唤醒词检测**，AudioInputTask 根据事件位判断是喂给唤醒词还是处理器。

### 3.5 音频输入任务的处理逻辑

文件：`audio/audio_service.cc:190-257`（AudioInputTask）

```
AudioInputTask 循环:
  ┌─ 等待事件位 (AS_EVENT_AUDIO_TESTING | WAKE_WORD | AUDIO_PROCESSOR)
  │
  ├─ AS_EVENT_AUDIO_TESTING → ReadAudioData() → 编码 → testing_queue
  │
  ├─ AS_EVENT_WAKE_WORD → ReadAudioData() → wake_word_->Feed()
  │
  └─ AS_EVENT_AUDIO_PROCESSOR → ReadAudioData() → audio_processor_->Feed()
                               ↓
                          VAD检测 / 回声消除 / 噪声抑制
                               ↓
                          PushTaskToEncodeQueue() → Opus编码 → 发送队列
```

## 4. 麦克风硬件控制（ES8311）

### 4.1 ES8311 编解码器初始化

文件：`audio/codecs/es8311_audio_codec.cc:15-56`

构造函数中完成以下配置：

```cpp
Es8311AudioCodec::Es8311AudioCodec(..., uint8_t es8311_addr, ...) {
    duplex_ = true;            // 全双工
    input_reference_ = false;   // 无参考输入
    input_channels_ = 1;        // 单通道麦克风输入
    input_gain_ = 30;           // 默认输入增益30
    // ...
    es8311_cfg.codec_mode = ESP_CODEC_DEV_WORK_MODE_BOTH;  // DAC + ADC 双工
    es8311_cfg.pa_pin = pa_pin;   // 功放控制引脚
    codec_if_ = es8311_codec_new(&es8311_cfg);
}
```

- `ESP_CODEC_DEV_WORK_MODE_BOTH` — ES8311 的 ADC（麦克风输入）和 DAC（扬声器输出）**都初始化**
- I2S 配置为 `I2S_SLOT_MODE_STEREO`（立体声模式），但 ES8311 的 ADC 只使用一个通道

### 4.2 `UpdateDeviceState()` — 硬件设备生命周期管理

文件：`audio/codecs/es8311_audio_codec.cc:56-79`

```cpp
void Es8311AudioCodec::UpdateDeviceState() {
    if ((input_enabled_ || output_enabled_) && dev_ == nullptr) {
        // 首次启用输入或输出时，创建编解码设备句柄
        dev_cfg.dev_type = ESP_CODEC_DEV_TYPE_IN_OUT;
        dev_ = esp_codec_dev_new(&dev_cfg);
        esp_codec_dev_open(dev_, &fs);           // 打开设备
        esp_codec_dev_set_in_gain(dev_, 30);     // 设置输入增益
        esp_codec_dev_set_out_vol(dev_, 70);     // 设置输出音量
    } else if (!input_enabled_ && !output_enabled_ && dev_ != nullptr) {
        esp_codec_dev_close(dev_);               // 关闭设备
        dev_ = nullptr;
    }
    // PA（功放）独立控制
    if (pa_pin_ != GPIO_NUM_NC) {
        int level = output_enabled_ ? 1 : 0;
        gpio_set_level(pa_pin_, pa_inverted_ ? !level : level);  // ← 功放引脚
    }
}
```

### 4.3 PA 和麦克风的独立控制

| 功能 | 控制方式 | 引脚 |
|------|----------|------|
| **麦克风 ADC** | I2C 控制 ES8311 内部寄存器（通过 `esp_codec_dev` API） | 无独立 GPIO |
| **功放 PA** | GPIO 电平控制（`gpio_set_level`） | `pa_pin_`（板级配置） |
| **I2S 数据** | DOUT（麦克风数据输出）、DIN（扬声器数据输入） | 板级引脚 |

**关键设计**：
- PA 使能**只与 `output_enabled_` 相关**，与麦克风是否启用无关
- 麦克风输入（ADC）只通过 I2C 寄存器控制，**没有独立的 GPIO 使能引脚**
- 关闭麦克风输入：调用 `EnableInput(false)` → `UpdateDeviceState()` → 如果两者都关闭则 `esp_codec_dev_close(dev_)`

### 4.4 BoxAudioCodec 的差异（ES8311 DAC + ES7210 ADC）

文件：`audio/codecs/box_audio_codec.cc`

对于使用独立 ADC 芯片（ES7210）的板子：
- DAC 通道使用 ES8311（`ESP_CODEC_DEV_WORK_MODE_DAC`）
- ADC 通道使用 ES7210（4 麦克风输入）
- **输入和输出使用不同的编解码器芯片**，可以独立控制

## 5. 屏蔽麦克风的具体方案

### 方案 A：在 `Application::Start()` 中强制禁用麦克风（最简单）

> **修改文件**: `esp32-firmware/main/application.cc`  
> **位置**: 第 363-364 行之后，在 `Initialize/Start` 调用之后立即关闭

```cpp
void Application::Start() {
    // ...
    auto codec = board.GetAudioCodec();
    audio_service_.Initialize(codec);
    audio_service_.Start();          // ← 原代码第 364 行

    // ★ 新增：启动后立即禁用麦克风输入
    codec->EnableInput(false);       // ← 新增代码

    AudioServiceCallbacks callbacks;
    // ...
```

**也可在 `audio_service_.Start()` 之后立即停止语音处理和唤醒词**：

```cpp
    audio_service_.Start();
    // ★ 新增：屏蔽所有麦克风相关功能
    audio_service_.EnableVoiceProcessing(false);
    audio_service_.EnableWakeWordDetection(false);
```

#### 修改后的预期效果

| 现象 | 预期 |
|------|------|
| 设备启动 | 正常启动，音频输出正常 |
| 语音交互 | **麦克风永久静音**，无法采集声音 |
| 唤醒词 | 不工作（因为唤醒词检测被关闭） |
| 音频输出 | 正常工作（扬声器播放 TTS 不受影响） |
| 电源管理 | 麦克风始终关闭，不会触发自动开启 |

#### 可能的影响和注意事项

- ⚠️ **影响**：`ReadAudioData()` 第 136-139 行可能会自动重新调用 `codec_->EnableInput(true)`。需要确认这个代码路径是否会被触发。
- ⚠️ **影响**：如果后续 `SetDeviceState(kDeviceStateListening)` 被调用，它会调用 `EnableVoiceProcessing(true)`，但该方法只设置事件位，不会直接调用 `codec_->EnableInput(true)`。然而音频输入任务在 `ReadAudioData()` 中检测到输入未启用时会自动开启麦克风（`audio_service.cc:136-139`）。
- **后果**：方案 A 只能在启动时关闭，**不能阻止运行时的恢复**。

📝 **参考此逻辑**：更可靠的做法是同时修改 `AudioService::ReadAudioData()` 中的自动开启逻辑。

---

### 方案 B：修改 `SetDeviceState()` 中的逻辑（更彻底）

> **修改文件**: `esp32-firmware/main/application.cc`  

#### B-1：所有状态都不启用麦克风

```cpp
void Application::SetDeviceState(DeviceState state) {
    // ...
    switch (state) {
        case kDeviceStateUnknown:
        case kDeviceStateIdle:
            // ★ 修改：空闲状态不启用任何麦克风功能
            audio_service_.EnableVoiceProcessing(false);
            audio_service_.EnableWakeWordDetection(false);  // ← 改为 false
            break;
        case kDeviceStateListening:
            // ★ 修改：不启用语音处理（但保持协议通信）
            display->SetStatus(Lang::Strings::LISTENING);
            display->SetEmotion("neutral");
            if (!audio_service_.IsAudioProcessorRunning()) {
                protocol_->SendStartListening(listening_mode_);
                // audio_service_.EnableVoiceProcessing(true);  // ← 注释掉
                // audio_service_.EnableWakeWordDetection(false);
            }
            break;
        case kDeviceStateSpeaking:
            display->SetStatus(Lang::Strings::SPEAKING);
            // 强制关闭语音处理
            audio_service_.EnableVoiceProcessing(false);
            audio_service_.EnableWakeWordDetection(false);
            break;
        // ...
    }
}
```

#### B-2：同时修改 `AudioService::ReadAudioData()` 取消自动开启

> **修改文件**: `audio/audio_service.cc:135-140`

```cpp
bool AudioService::ReadAudioData(std::vector<int16_t>& data, int sample_rate, int samples) {
    if (!codec_->input_enabled()) {
        esp_timer_stop(audio_power_timer_);
        esp_timer_start_periodic(audio_power_timer_, AUDIO_POWER_CHECK_INTERVAL_MS * 1000);
        // codec_->EnableInput(true);  // ← 注释掉或加条件
    }
    // ...
}
```

#### 修改后的预期效果

| 现象 | 预期 |
|------|------|
| 设备空闲 | 唤醒词不工作，麦克风完全关闭 |
| 语音交互 | **无法采集声音**，VAD 永远为 false |
| 服务器交互 | 心跳、OTA 等协议正常 |
| "开始聆听"操作 | 协议通道正常打开，但不采集麦克风数据 |
| 音频输出 | 完全正常 |

#### 可能的影响和注意事项

- ⚠️ **影响**：如果 `ReadAudioData()` 不修改，当任何代码路径触发 `AudioInputTask` 运行时，仍然会调用 `codec_->EnableInput(true)`。方案 B 必须**同时**修改 `ReadAudioData()`。
- ⚠️ **影响**：`AudioInputTask` 在等待事件位时（`AS_EVENT_WAKE_WORD_RUNNING` 或 `AS_EVENT_AUDIO_PROCESSOR_RUNNING`），如果这些位没有设置，任务会堵塞在 `xEventGroupWaitBits`。所以从逻辑上，只要不设置这些事件位，`ReadAudioData` 不会被调用。

void Es8311AudioCodec::UpdateDeviceState() {
    if (output_enabled_ && dev_ == nullptr) {      // ← 只检查 output_enabled_
        dev_cfg.dev_type = ESP_CODEC_DEV_TYPE_OUT; // ← 改为 OUT 而非 IN_OUT
        dev_ = esp_codec_dev_new(&dev_cfg);
        esp_codec_dev_open(dev_, &fs);
        // esp_codec_dev_set_in_gain 不再需要
        esp_codec_dev_set_out_vol(dev_, output_volume_);
    } else if (!output_enabled_ && dev_ != nullptr) {  // ← 只检查输出
        esp_codec_dev_close(dev_);
        dev_ = nullptr;
    }
    if (pa_pin_ != GPIO_NUM_NC) {
        int level = output_enabled_ ? 1 : 0;
        gpio_set_level(pa_pin_, pa_inverted_ ? !level : level);
    }
}
