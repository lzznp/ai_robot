### 1.2 `DeviceManager.get_connection()` — 返回的是 WebSocket 对象

**文件**：`core/device_manager.py`，第 28-36、77-79 行

```python
class DeviceManager:
    def __init__(self):
        self._connections: Dict[str, Any] = {}   # ← device_id → websocket

    async def register(self, device_id, websocket, metadata=None):
        self._connections[device_id] = websocket   # ← 存的是 raw WebSocket！

    def get_connection(self, device_id):
        """获取设备的 WebSocket 连接对象"""
        return self._connections.get(device_id)    # ← 返回 WebSocket，不是 ConnectionHandler！
```

### 1.5 `SceneDispatcher.dispatch_actions()` — TTS 下发

**文件**：`core/scene_dispatcher.py`，第 177-225 行

```python
async def dispatch_actions(self, actions: List[Dict]):
    if not self.device_manager:
        return
    for action in actions:
        target = action.get("target")
        if action.get("type") == "tts":
            text = action.get("text", "")
            if self.connection_handler:
                # ★ 走完整 TTS 链路 ★
                await self.device_manager.send(target, {
                    "type": "stt", "text": text,
                    "session_id": self.connection_handler.session_id
                })
                self.connection_handler.tts.tts_one_sentence(  # ← 触发 TTS 生成
                    self.connection_handler,
                    ContentType.TEXT,
                    content_detail=text
                )
            else:
                # 没有 connection_handler，只发信令
                await self.device_manager.send(target, {
                    "type": "tts", "state": "sentence_start", "text": text
                })
```

## 4. 中断点 / 异常点

### 🔴 中断点 1（致命）：`dm.get_connection()` 返回 WebSocket 而非 ConnectionHandler

**位置**：`command_api.py:175` → `device_manager.py:79`

**现象**：
- `DeviceManager._connections` 存储的是 `WebSocket` 对象（见 `device_manager.py:34`）
- `get_connection(device_id)` 返回 `WebSocket`
- `/api/text` 中 `hasattr(conn, 'test_scene_dispatcher')` 检查失败
- 接口永远返回 `"test_scene_dispatcher 方法不存在"`

**根因**：
`DeviceManager` 设计为管理设备连接的 WebSocket 池，并未保存 `ConnectionHandler` 引用。/api/text 开发者误以为 `get_connection()` 返回的是 `ConnectionHandler`。

**影响**：
- `/api/text` 接口**完全无法工作**
- 即使工作，后续的 `conn.test_scene_dispatcher(text)` 也无法调用

### 🔴 中断点 2（结构风险）：`SceneDispatcher.process()` 依赖 `self.world.process()`

**位置**：`scene_dispatcher.py:112`

**现象**：
```python
raw_results = self.world.process(user_input)
```

`SceneDispatcher` 虽然包装了 `World`，但 `process()` 内部仍然直接调用 `World.process()`。如果 `World` 类发生变更或弃用，`SceneDispatcher` 会连锁故障。

**影响**：
- World 是 `dooirobot` 项目的遗留模块
- `World.process()` 内部调用 `Character.say()` → `LLM`，构成完整依赖链

### 🔶 中断点 3（潜在）：`scene_dispatcher` 未初始化时 `/api/text` 无回退

**位置**：`command_api.py:181-187`（/api/text）

`test_scene_dispatcher` 内部检查了 `scene_dispatcher is None`（connection.py:606），但 `/api/text` 没有提供任何回退逻辑。如果场景调度器未初始化，用户文本消息会被静默丢弃。

### 🔶 中断点 4（潜在）：`ConnectionHandler._init_scene_dispatcher()` 可能静默失败

**位置**：`connection.py:254-288`

如果 `SceneDispatcher` 初始化过程中出现异常，`scene_dispatcher` 被设为 `None`，但 ConnectionHandler 自身继续运行。后续调用 `process_with_scene()` 或 `test_scene_dispatcher()` 时只能返回空结果。

### ⚠️ 注意点 5：音频流通过 `DeviceManager.send()` 和 `conn.websocket.send()` 两条通道

- **TTS 信令**（STT 文本、情感）：通过 `DeviceManager.send()` → `WebSocket.send(json)`
- **TTS 音频数据**：通过 `connection_handler.tts.tts_one_sentence()` 触发后台线程 → `conn.websocket.send(opus_bytes)`

两条通道都最终写入 `WebSocket`，但一个走 DeviceManager 的 `_connections` 字典，另一个走 ConnectionHandler 自己的 `self.websocket`。在多设备场景中，如果 `DeviceManager` 的 WebSocket 和 ConnectionHandler 的 `self.websocket` 不是同一个对象，可能出现 TTS 文本信令发到 A 设备、音频发到 B 设备的情况。

## 5. 修复建议

### 5.1 修复 `/api/text` — 获取真正的 ConnectionHandler

**方案 A（推荐）**：在 `DeviceManager` 中添加 `ConnectionHandler` 映射

```python
# device_manager.py 新增
self._handlers: Dict[str, ConnectionHandler] = {}

def register_handler(self, device_id: str, handler: ConnectionHandler):
    self._handlers[device_id] = handler

def get_handler(self, device_id: str) -> Optional[ConnectionHandler]:
    return self._handlers.get(device_id)
```

在 `ConnectionHandler` 初始化完成后调用 `dm.register_handler(device_id, self)`。  
`/api/text` 改为：

```python
handler = dm.get_handler(device_id)
if not handler:
    return web.json_response({'success': False, 'message': f'设备 {device_id} 不在线或无 handler'})

result = await handler.test_scene_dispatcher(text)
```

**方案 B（最小改动）**：在 `/api/text` 中尝试从 `request.app` 或其他字典中查找 handler

```python
# 在 server 中维护一个 device_id → ConnectionHandler 的映射
handler = request.app.get('connection_handlers', {}).get(device_id)
```

### 5.2 考虑解耦 `SceneDispatcher` 与 `World`

在 `scene_dispatcher.py` 中，`SceneDispatcher.process()` 调用 `self.world.process()`：

```python
raw_results = self.world.process(user_input)
```

如果希望消除对 World 的依赖，可以直接在 `SceneDispatcher.process()` 中实现角色识别和 LLM 调用逻辑，而不是委托给 `World`。但当前 `World` 作为中间层提供了 `detect_target()` 和 `Character.say()` 等封装，短期内建议保留。

### 5.3 为 `/api/text` 增加回退策略

当 `test_scene_dispatcher` 不可用时，应回退到原始 LLM 对话流程：

```python
result = await handler.test_scene_dispatcher(text)
if not result.get("success"):
    # 回退：直接走 LLM chat 流程
    handler.executor.submit(handler.chat, text)
    return web.json_response({"success": True, "message": "已通过 LLM 下发"})
```

### 5.4 统一 TTS 下发通道

在 `scene_dispatcher.py:dispatch_actions()` 中，**既有** `DeviceManager.send()` 的 STT 信令，**又有** `connection_handler.tts.tts_one_sentence()` 的音频。建议两者都通过 `connection_handler` 统一走内部队列，避免 `DeviceManager.send()` 和 `conn.websocket.send()` 两条路径潜在的 WebSocket 实例不一致问题。

## 6. 总结

| 侦察项 | 结论 |
|--------|------|
| `/api/text` 获取的 conn 类型 | **`WebSocket` 对象**（来自 `DeviceManager._connections`） |
| conn 是否有 `test_scene_dispatcher`？ | **没有**（WebSocket 没有该方法） |
| conn 是否有 `process_with_scene`？ | **ConnectionHandler 有**，但 `/api/text` 拿不到 ConnectionHandler |
| `process_with_scene` 是否调 `SceneDispatcher.process()`？ | **是**（connection.py:595） |
| `SceneDispatcher.process()` 是否调 `self.world.process()`？ | **是**（scene_dispatcher.py:112 — 仍依赖 World） |
| TTS 音频最终下发方式 | `conn.websocket.send(opus_bytes)`（直接二进制） |
| **整体链路是否通畅？** | **❌ 中断** — `/api/text` 获取不到 ConnectionHandler |

**核心问题**：`DeviceManager.get_connection()` 返回 WebSocket，不是 ConnectionHandler，导致 `/api/text` 接口检测不到目标方法而提前返回。

**修复优先级**：
1. 🔴 **致命**：修复 `/api/text` 获取 ConnectionHandler 的途径（见 5.1）
2. 🟡 **重要**：统一 TTS 下发通道，避免 WebSocket 对象不一致（见 5.4）
3. 🟢 **建议**：`SceneDispatcher` 解耦 World（见 5.2）
