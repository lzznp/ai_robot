## 1. app.py — 启动入口

**用途**：服务器启动脚本，负责配置加载、服务注册、生命周期管理。

- **代码行数**：178 行（旧版 152 行，+26 行）
- **当前状态**：✅ 已修改
- **旧版对比**：旧版 `app.py` 仅启动 WebSocket + OTA 服务；新版新增了 aiohttp API 服务和 device_manager 桥接

### 核心流程

```
main()
├── check_ffmpeg_installed()
├── load_config() → config
├── [NEW] auth_key 生成逻辑（config > manager-api.secret > uuid.uuid4）
├── monitor_stdin() 任务（消费回车键）
├── start GC manager（5分钟周期）
├── start WebSocketServer → ws_server
├── ── WS 启动后获取 ws_server.device_manager
├── [NEW] 创建 aiohttp web app
│   ├── app["device_manager"] = device_manager
│   ├── POST /api/command  → send_command()
│   └── GET  /api/devices  → get_devices()
├── [NEW] 启动 API 服务（0.0.0.0:8004）
├── start SimpleHttpServer（OTA，port 8003）
├── 日志输出：OTA 地址、视觉接口、MCP 端点、WS 地址
├── wait_for_exit()   ← 阻塞主协程
└── finally: cleanup → stop GC, cancel tasks, wait with timeout 3s
```

### 关键变更

| 变更项 | 旧版 | 新版 |
|--------|------|------|
| HTTP API 服务 | ❌ 无 | ✅ 新增 `aiohttp` app，端口 8004 |
| API 路由 | ❌ | `POST /api/command` + `GET /api/devices` |
| `device_manager` 引用 | ❌ | 从 `ws_server` 获取并注入到 API app |
| auth_key 生成 | 固定逻辑 | 三级 fallback：config → manager-api.secret → uuid |
| 清理逻辑 | 基本 | 增加 `api_runner.cleanup()` + 超时等待 |

## 2. core/device_manager.py — 设备管理

**用途**：设备连接管理器，替代旧版 `websocket_server.connections` 字典。提供设备注册/注销/发送/广播/心跳的统一接口。

- **代码行数**：111 行
- **当前状态**：✅ **全新**，活跃使用
- **被引用方**：`websocket_server.py`、`command_sender.py`、`command_api.py`、`scene_dispatcher.py`、`web_console/services/`

### 核心类：`DeviceManager`

```python
class DeviceManager:
    _connections: Dict[str, Any]     # device_id → websocket
    _device_info: Dict[str, Dict]    # device_id → 元信息（online, last_seen, registered_at, capabilities...）
    _lock: asyncio.Lock              # 线程安全锁
```

### 方法清单

| 方法 | 说明 | 调用方 |
|------|------|--------|
| `register(device_id, websocket, metadata)` | 注册设备连接 | `websocket_server._handle_connection` |

### process() 流程图

```
process(text, device_id)
├── set_current_device(device_id)
├── world.process(text)           ← 委托旧 World
│   ├── detect_target(text) → 角色名
│   ├── character.say(text) → 回复文本
│   └── return ["角色名: 台词", ...]
├── 解析 raw_results
│   ├── "角色名: 台词" → 拆分为 role_name + text
│   ├── 查找 role_device_map → target_device_id
│   └── 生成 actions: [tts_action, emotion_action, ...]
└── return {"actions": [...], "response": "...", "raw_results": [...]}
```

### dispatch_actions() 痛点

`dispatch_actions` 中 TTS 下发存在**两种路径**，硬编码判断导致逻辑割裂：

```
dispatch_actions(actions)
├── action.type == "tts"
│   ├── ★ 有 connection_handler → 完整 TTS 链路
│   │   ├── 1. send({"type": "stt", "text": "...", "session_id": ...})
│   │   └── 2. connection_handler.tts.tts_one_sentence(...)
│   └── ★ 无 connection_handler → 只发信令
│       └── send({"type": "tts", "state": "sentence_start", "text": "..."})
├── action.type == "emotion"
│   └── send({"type": "llm", "emotion": "..."})
├── action.type == "action"
│   └── send({"type": "action", "action": "..."})
└── else: log warning
```

       ├─→ LLMAdapter (待合并)

## 6. core/world.py — 多角色调度（待废弃）

**用途**：管理多个 Character 角色，识别用户对话目标，将输入路由到对应角色处理。

- **代码行数**：119 行
- **当前状态**：⚠️ **待废弃** — 功能已被 `SceneDispatcher` 替代，但 `SceneDispatcher.process()` 内部仍在委托 `World.process()`

### 核心类：`World`

```python
class World:
    llm: Callable                       # LLM 客户端
    characters: Dict[str, Character]    # 角色注册表
    default_character: str              # 默认角色
    global_history: List[Dict]          # 全局对话历史（最多 50 条）
```

### 核心方法

| 方法 | 说明 |
|------|------|
| `add_character(character)` | 注册角色 |
| `set_default(name)` | 设置默认角色 |
| `detect_target(user_input)` → str | 识别对话目标（@匹配 → 开头匹配 → 关键词同音字 → 默认） |
| `process(user_input)` → `["角色: 台词"]` | 处理输入，返回调度结果 |
| `add_to_history(speaker, content)` | 添加对话到全局历史 |

### detect_target() 匹配优先级

```
1. @角色名  → 精确匹配
2. 开头匹配 → "MOSS你好" → "MOSS"
3. 关键词   → "瓦力"/"瓦丽"/"威力" → "瓦力"
               "MOSS"/"莫斯"       → "MOSS"
               "Doly"/"多利"       → "Doly"
4. 默认     → default_character 或第一个注册的角色
```

### 待废弃原因

`SceneDispatcher` 已提供更完整的封装（场景切换 + 动作下发 + 设备映射），但当前 `SceneDispatcher.process()` 内部仍调用 `self.world.process()`，形成两层委托：

```
SceneDispatcher.process()
  └── World.process()
        ├── detect_target(text)   → 角色名
        ├── character.say(text)   → LLM 调用
        └── 返回 ["角色: 台词"]
```

**迁移方向**：将 World.process() 的逻辑内联到 SceneDispatcher 中，消除间接委托。

## 11. 待重构项总结
