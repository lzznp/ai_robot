void Protocol::SendStartListening(ListeningMode mode) {
    std::string message = "{\"session_id\":\"" + session_id_ + "\"";
    message += ",\"type\":\"listen\",\"state\":\"start\"";      // ← state = "start"
    if (mode == kListeningModeRealtime) {
        message += ",\"mode\":\"realtime\"";
    } else if (mode == kListeningModeAutoStop) {
        message += ",\"mode\":\"auto\"";
    } else {
        message += ",\"mode\":\"manual\"";
    }
    message += "}";
    SendText(message);
}

## 3. 三个 state 的处理逻辑对比

### 3.1 完整 Listen 消息处理器

**文件**: `core/handle/textHandler/listenMessageHandler.py:20-66`

```python
async def handle(self, conn, msg_json):
    # ... 处理 mode ...

    if msg_json["state"] == "start":
        # 设备从播放模式切回录音模式,清除所有音频状态和缓冲区
        conn.reset_audio_states()
        # ★ 没有调用 startToChat()

    elif msg_json["state"] == "stop":
        conn.client_voice_stop = True
        if conn.asr.interface_type == InterfaceType.STREAM:
            asyncio.create_task(conn.asr._send_stop_request())
        else:
            if len(conn.asr_audio) > 0:
                asr_audio_task = conn.asr_audio.copy()
                conn.reset_audio_states()
                if len(asr_audio_task) > 0:
                    await conn.asr.handle_voice_stop(conn, asr_audio_task)
                    # ★ handle_voice_stop → startToChat (通过音频)

    elif msg_json["state"] == "detect":
        conn.client_have_voice = False
        conn.reset_audio_states()
        if "text" in msg_json:
            original_text = msg_json["text"]
            filtered_len, filtered_text = remove_punctuation_and_length(original_text)
            is_wakeup_words = filtered_text in conn.config.get("wakeup_words")
            enable_greeting = conn.config.get("enable_greeting", True)

            if is_wakeup_words and not enable_greeting:
                await send_stt_message(conn, original_text)
                await send_tts_message(conn, "stop", None)
                # ← 唤醒词且不回复 → 不发 LLM
            elif is_wakeup_words:
                await startToChat(conn, "嘿，你好呀")          # ← 唤醒词回复
            else:
                await startToChat(conn, original_text)           # ← ★ 正常文本对话入口
```

### 3.2 三个 state 的对比

| state | 触发条件 | 调用 startToChat? | 文本来源 |
|---|---|---|---|
| `"start"` | 固件进入 Listening 模式 | ❌ **不调用** | 无文本 |
| `"stop"` | 固件停止拾音 | ✅ **间接调用** | 通过 `handle_voice_stop`（ASR 转文字） |
| `"detect"` | GUI 文字输入 / 唤醒词检测 | ✅ **直接调用** | `msg_json["text"]` 字段 |

## 6. 结论

### 6.1 如果 startToChat 没被调用，问题出在哪个环节

**两种情况**：

| 场景 | 发送的 state | 结果 |
|---|---|---|
| **GUI 发送 `state="start"`** | `"start"` | ❌ startToChat 不被调用。`"start"` 状态仅清空音频缓冲区，不会触发对话 |
| **GUI 发送 `state="detect"`** | `"detect"` | ✅ startToChat 被调用（前提是 `"text"` 字段存在） |

**所以根本问题是**：GUI 可能发送了 `state="start"` 而不是 `state="detect"`。

### 6.2 修复建议

#### 方案 A（推荐）：GUI 发送正确的 state

GUI 发送文本时应使用 `state="detect"`：
```json
{"type":"listen","state":"detect","text":"大家好","mode":"auto"}
```

#### 方案 B（兼容性）：在 `"start"` 处理分支中增加文本检测

如果某些 GUI 发送 `state="start"` 并带有 text 字段，可在 `listenMessageHandler.py:28` 的 `"start"` 分支增加兼容逻辑：

```python
if msg_json["state"] == "start":
    conn.reset_audio_states()
    # ★ 新增：如果 start 消息也带了 text 字段
    if "text" in msg_json:
        conn.logger.bind(tag=TAG).info("start消息携带文本，兼容处理")
        await startToChat(conn, msg_json["text"])
        return
```

#### 方案 C（固件侧）：检查固件是否在特定场景发送了 `"detect"` 消息

如果是固件触发的发送，确认固件在唤醒词检测后是否发送了 `{"type":"listen","state":"detect","text":"..."}` 而非 `"start"`。
