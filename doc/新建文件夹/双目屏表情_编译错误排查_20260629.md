# 双目屏表情编译错误排查报告

**日期**: 2026-06-29
**问题**: `fatal error: ui_emoji_dualeye.h: No such file or directory`

---

## 1. 文件存在性检查

### 实际文件清单

| 文件 | 路径 | 存在? |
|---|---|---|
| `ui_emoji_dualeye.h` | `main/boards/waveshare-s3-dualeye-lcd-1.28/ui_emoji_dualeye.h` | ❌ **不存在** |
| `ui_emoji.h` | `main/boards/waveshare-s3-dualeye-lcd-1.28/ui_emoji.h` | ✅ **存在** |
| `ui_emoji_dualeye.cc` | `main/boards/waveshare-s3-dualeye-lcd-1.28/ui_emoji_dualeye.cc` | ✅ **存在** |

### 根因

**文件名不匹配**：实际头文件的文件名为 `ui_emoji.h`，但所有 `.cc` 文件中的 `#include` 均为 `"ui_emoji_dualeye.h"`。

```
磁盘上的文件:              ui_emoji.h               ← ★ 实际文件名
编译器要找的文件:          ui_emoji_dualeye.h       ← ★ include 指令

三个文件都引用了错误的文件名:
  display_manager.cc         第5行:  #include "ui_emoji_dualeye.h"  ← 不存在
  esp32-s3-dualeye-lcd-1.28.cc  第21行:  #include "ui_emoji_dualeye.h"  ← 不存在
  ui_emoji_dualeye.cc        第8行:  #include "ui_emoji_dualeye.h"  ← 不存在
```

注意，虽然 `ui_emoji.h` 内部的 `#ifndef` 保护宏写的是 `UI_EMOJI_DUALEYE_H`，但**保护宏的名称不影响文件名查找**。编译器只根据 `#include` 指令中的字符串找磁盘文件。

---

```cmake
    # ★★★ 添加头文件目录 ★★★
    list(APPEND INCLUDE_DIRS
        "${CMAKE_CURRENT_SOURCE_DIR}/boards/waveshare-s3-dualeye-lcd-1.28")
```

**检查结论**：

| 检查项 | 结果 |
|---|---|
| 源文件路径 | ✅ 正确 —— `${CMAKE_CURRENT_SOURCE_DIR}/boards/waveshare-s3-dualeye-lcd-1.28/ui_emoji_dualeye.cc` |
| 头文件目录 | ✅ 正确 —— `INCLUDE_DIRS` 添加了 board 目录，编译器会在该目录下搜索头文件 |
| 条件分支 | ✅ 正确 —— `CONFIG_BOARD_TYPE_WAVESHARE_S3_DUALEYE_LCD_1_28` 分支内 |
| **CMake 缓存问题** | ❌ **不相关** —— 文件根本不存在，清缓存无意义 |

**结论**：CMakeLists.txt 配置正确，问题是头文件丢失，不是编译配置问题。

## 4. 修复方案

### 方案 A（推荐）：重命名头文件

将 `ui_emoji.h` 重命名为 `ui_emoji_dualeye.h`，与 `#include` 指令匹配。

```bash
# Windows PowerShell
cd D:\study\ai_robot\esp32-firmware\main\boards\waveshare-s3-dualeye-lcd-1.28
Rename-Item ui_emoji.h ui_emoji_dualeye.h
```

### 方案 B：修改所有 include 为实际文件名

如果不想改文件名，把所有引用改为 `"ui_emoji.h"`：

| 文件 | 行号 | 修改前 | 修改后 |
