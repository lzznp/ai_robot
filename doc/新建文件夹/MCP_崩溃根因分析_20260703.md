# MCP 初始化崩溃根因分析报告

> **日期**: 2026-07-03
> **板子**: lingkong-s3-moc-cam-1.54tft（瓦力）
> **问题**: 收到 MCP initialize 后固件崩溃重启（InstructionFetchError）

---

## 一、问题概述

### 1.1 现象
- 固件 WiFi 连接成功（IP: 192.168.199.102）
- WebSocket 握手成功，收到 server hello
- 后台收到设备的 hello、listen、mcp 消息
- **后台发送 `{"type":"mcp","payload":{"jsonrpc":"2.0","method":"initialize","params":{"capabilities":{...}},"id":1}}` 后，固件立即崩溃**

### 1.2 错误日志
```
Guru Meditation Error: Core 0 panic'ed (InstructionFetchError). Exception was unhandled.
PC: 0x3fcec7dc  无效地址（栈已损坏）
Backtrace: 0x3fcec7d9:0x3fcb3480 |<-CORRUPTED
```

### 1.3 关键特征
| 特征 | 含义 |
|------|------|
| `InstructionFetchError` | CPU 试图从无效内存地址取指令 |
| PC = `0x3fcec7dc` | 崩溃地址在 **PSRAM 地址空间**（0x3f000000–0x3fffffff） |
| Backtrace `CORRUPTED` | 栈已被破坏，无法还原调用链 |

## 三、根因分析：camera_ 未初始化（野指针崩溃）

### 3.1 问题定位

在 `lingkong-s3-moc-cam-1.54tft.cc` 中：

```cpp
class LichuangDevBoard : public WifiBoard {
private:
    ...
    Esp32Camera* camera_;        // ← 声明，但从未初始化！
    ...

    LichuangDevBoard() : boot_button_(BOOT_BUTTON_GPIO) {
        InitializePowerManager();
        InitializeI2c();
        InitializeSpi();
        InitializeSt7789Display();
        InitializeButtons();
        //InitializeCamera();     // ← 注释掉了！camera_ 没有被赋值
    }

    virtual Camera* GetCamera() override {
        return camera_;          // ← 返回垃圾值（未初始化指针）
    }
};
```

**根因**：`camera_` 成员指针：
1. **未在成员初始化列表中初始化**
2. **未在构造函数体内赋值**（`InitializeCamera()` 被注释）
3. 基类 `Board::GetCamera()` 返回 `nullptr`，但 Lingkong 板子 **重写了** `GetCamera()` 返回 `camera_`

因为 `DECLARE_BOARD` 宏使用 `new BOARD_CLASS_NAME()` 创建板子实例（堆分配），堆内存**不会自动清零**，所以 `camera_` 的值是**栈或堆上遗留的垃圾地址**。

### 3.2 崩溃机理

```
ParseCapabilities()
  → Board::GetInstance().GetCamera()
    → LichuangDevBoard::GetCamera()
      → return camera_    ← 返回垃圾地址，例如 0x3fXXXXXX（PSRAM 区域）
  → if (camera)           ← 垃圾地址非空，条件通过！
  → camera->SetExplainUrl()  ← 虚函数调用
    → vtable 指针从垃圾地址读取
      → vtable 内容也是垃圾
        → 函数指针指向 PSRAM 中的随机地址
          → CPU 试图从该地址取指令
            → InstructionFetchError!
```

### 3.3 为什么双目屏不崩溃？

双面屏板子（`waveshare-s3-dualeye-lcd-1.28`）**没有摄像头**，且 **没有重写 `GetCamera()`**：
- 调用 `Board::GetCamera()` → 基类返回 `nullptr`
- `if (camera)` → false → 跳过 `SetExplainUrl`
- 所以不会崩溃

### 3.4 栈损坏的原因

`InstructionFetchError` 发生后，异常处理试图记录调用栈。但因为栈帧已经被**虚函数调用过程中的栈操作**覆盖（或者栈指针本身由于跳转到非法代码而损坏），无法生成有效的 backtrace。

## 四、其他可能原因（已排除）

### 原因 B：TCP 接收任务栈溢出

| 项目 | 值 |
|------|-----|
| TCP 接收任务栈大小 | 4096 字 = **16 KB** |
| 处理 MCP initialize 的调用深度 | OnTcpData → cJSON_Parse → OnIncomingJson → ParseMessage → ReplyResult → Schedule |
| cJSON_Parse 递归深度 | MCP initialize JSON 只有 2-3 层嵌套 |
| **结论** | 16 KB 栈足够，且双目屏也在同样的任务中处理 MCP，栈溢出**可能性低** |

### 原因 C：cJSON use-after-free

WebSocket 回调中 `cJSON_Delete(root)` 在 `on_incoming_json_` 返回后才执行，`ParseMessage` 中使用的 `payload` 指针在调用期间仍有效，不存在 use-after-free。**已排除。**

### 原因 D：ReplyResult/Schedule 中的重入问题

`Schedule` 使用 mutex 保护队列操作，简单安全。`SendMcpMessage` 中在主线程发送，不在回调中直接发送。**已排除。**

## 五、修复方案

### 方案 1（推荐）：初始化 camera_ 为 nullptr

在 `lingkong-s3-moc-cam-1.54tft.cc` 中修复未初始化指针：

```cpp
// ===== 修改前 =====
class LichuangDevBoard : public WifiBoard {
private:
    ...
    Esp32Camera* camera_;        // ← 未初始化
    ...
};

// ===== 修改后 =====
class LichuangDevBoard : public WifiBoard {
private:
    ...
    Esp32Camera* camera_ = nullptr;   // ← 显式初始化为 nullptr
    ...
};
```

**优点**：
- 最小改动，只加 `= nullptr`
- `if (camera)` 检查会跳过，安全
- 不影响其他板子

**缺点**：
- 如果后续需要相机，记得取消 `InitializeCamera()` 的注释

### 方案 2：删除 GetCamera 重写，使用基类默认值

```cpp
// ===== 修改前 =====
virtual Camera* GetCamera() override {
    return camera_;          // 返回野指针
}

// ===== 修改后 =====
// 删除 GetCamera() 重写 — 让基类 Board::GetCamera() 返回 nullptr
```

**优点**：
- 彻底消除野指针风险

**缺点**：
- 如果后续需要相机，需要恢复重写

### 方案 3：在 ParseCapabilities 中加强安全检查（防御性）

```cpp
// mcp_server.cc:342-344
auto camera = Board::GetInstance().GetCamera();
if (camera) {
    // 虽然 camera 非空，但可以添加一个 valid 检查
    // 不过无法在通用层面检测野指针
}
```

**不推荐**：无法在通用层面区分野指针和有效指针。

## 七、总结

| 项目 | 内容 |
|------|------|
| **根本原因** | `camera_` 指针未初始化，`ParseCapabilities` 调用 `camera->SetExplainUrl()` 时触发野指针崩溃 |
| **触发条件** | 后台下发 MCP initialize 且 capabilities 中包含 vision 字段 |
| **为什么双目屏正常** | 双目屏板子没有摄像头，未重写 `GetCamera()`，基类返回 nullptr 跳过 |
| **InstructionFetchError** | 野指针的 vtable 指向 PSRAM 中无代码的区域，CPU 取指令失败 |
| **推荐修复** | `Esp32Camera* camera_ = nullptr;`（初始化列表 + =nullptr） |
| **验证方法** | 烧录后确认 MCP initialize 不再触发崩溃，后续交互正常 |
