## 1. TTS JSON 消息处理

### 1.1 OnIncomingJson 回调

**文件**: `application.cc:449-480`

```cpp
protocol_->OnIncomingJson([this, display](const cJSON* root) {
    auto type = cJSON_GetObjectItem(root, "type");
    if (strcmp(type->valuestring, "tts") == 0) {
        auto state = cJSON_GetObjectItem(root, "state");

        // ① state == "start"
        if (strcmp(state->valuestring, "start") == 0) {
            Schedule([this]() {
                aborted_ = false;
                if (device_state_ == kDeviceStateIdle || device_state_ == kDeviceStateListening) {
                    SetDeviceState(kDeviceStateSpeaking);
                }
            });

        // ② state == "stop"
        } else if (strcmp(state->valuestring, "stop") == 0) {
            Schedule([this]() {
                if (device_state_ == kDeviceStateSpeaking) {
                    if (listening_mode_ == kListeningModeManualStop) {
                        SetDeviceState(kDeviceStateIdle);
                    } else {
                        SetDeviceState(kDeviceStateListening);
                    }
                }
            });

        // ③ state == "sentence_start"
        } else if (strcmp(state->valuestring, "sentence_start") == 0) {
            auto text = cJSON_GetObjectItem(root, "text");
            if (cJSON_IsString(text)) {
                ESP_LOGI(TAG, "<< %s", text->valuestring);
                Schedule([this, display, message = std::string(text->valuestring)]() {
                    display->SetChatMessage("assistant", message.c_str());
                });
            }
        }
    }
});
```

### 1.2 三个 state 的处理总结

| state | 处理方式 | 副作用 | 说明 |
|---|---|---|---|
| `"start"` | `Schedule` → `SetDeviceState(Speaking)` | 调用 `ResetDecoder`（条件化） | 进入说话状态 |
| `"stop"` | `Schedule` → `SetDeviceState(Listening/Idle)` | 无队列清理 | 退出说话状态 |
| `"sentence_start"` | `Schedule` → 更新显示文字 | 仅 UI | 不影响状态机 |

**关键发现**：三种 state 均通过 `Schedule()` 异步执行，不会在 WebSocket 线程中即时修改状态。

## 2. OnIncomingAudio 回调

**文件**: `application.cc:425-433`

```cpp
protocol_->OnIncomingAudio([this](std::unique_ptr<AudioStreamPacket> packet) {
    AudioStreamPacket* raw_packet = packet.release();
    Schedule([this, raw_packet]() {
        std::unique_ptr<AudioStreamPacket> p(raw_packet);
        if (device_state_ == kDeviceStateSpeaking) {
            audio_service_.PushPacketToDecodeQueue(std::move(p));
        }
    });
});
```

### 2.1 处理逻辑

| 要点 | 详情 |
|---|---|
| **执行线程** | WebSocket 库的网络回调线程 |
| **处理方式** | 通过 `Schedule()` 转发到主循环 |
| **入队条件** | 主循环执行时 `device_state_ == kDeviceStateSpeaking` |
| **入队目标** | `audio_decode_queue_`（带互斥锁） |
| **非 Speaking 时的处理** | **静默丢弃** |

### 2.2 Schedule 机制保证的时序

```
WebSocket 线程                main_tasks_ 队列              MainEventLoop 主循环
───────────────              ─────────────────             ──────────────────────
收到 "start" JSON
→ Schedule(SetSpeaking)
                              入队顺序:
                              [0] SetSpeaking
                              
收到 Opus 二进制帧                                           ↓ 处理 [0]
→ Schedule(PushDecode)             [0] SetSpeaking           SetDeviceState(Speaking)
                                  [1] PushDecode            → ResetDecoder
                                                              设备状态 = Speaking
                                                              
                                                             ↓ 处理 [1]
                                                             检查状态 == Speaking → ✅ 入队
                              
收到 Opus 二进制帧
→ Schedule(PushDecode)             [0] SetSpeaking           ↓ 处理 [2]
                                  [1] PushDecode            检查状态 == Speaking → ✅ 入队
                                  [2] PushDecode

收到 "stop" JSON
→ Schedule(SetListening)           [0] SetSpeaking           ↓ 处理 [3]
                                  [1] PushDecode            SetDeviceState(Listening)
                                  [2] PushDecode             设备状态 = Listening
                                  [3] SetListening
```

**结论**：由于 FIFO 队列顺序，`SetDeviceState(Speaking)` 一定在所有音频包之前执行，消除竞态条件。

## 3. SetDeviceState 状态切换

**文件**: `application.cc:681-737`

```cpp
void Application::SetDeviceState(DeviceState state) {
    if (device_state_ == state) return;
    
    clock_ticks_ = 0;
    auto previous_state = device_state_;   // ← 保存前状态
    device_state_ = state;
    ESP_LOGI(TAG, "STATE: %s", STATE_STRINGS[device_state_]);

    DeviceStateEventManager::GetInstance().PostStateChangeEvent(previous_state, state);

    auto& board = Board::GetInstance();
    auto display = board.GetDisplay();
    auto led = board.GetLed();
    led->OnStateChanged();
    
    switch (state) {
        case kDeviceStateIdle:
            display->SetStatus(Lang::Strings::STANDBY);
            display->SetEmotion("neutral");
            audio_service_.EnableVoiceProcessing(false);
            audio_service_.EnableWakeWordDetection(true);
            break;

        case kDeviceStateListening:
            display->SetStatus(Lang::Strings::LISTENING);
            display->SetEmotion("neutral");
            if (!audio_service_.IsAudioProcessorRunning()) {
                protocol_->SendStartListening(listening_mode_);
                audio_service_.EnableVoiceProcessing(true);
                audio_service_.EnableWakeWordDetection(false);
            }
            break;

        case kDeviceStateSpeaking:
            display->SetStatus(Lang::Strings::SPEAKING);
            if (listening_mode_ != kListeningModeRealtime) {
                audio_service_.EnableVoiceProcessing(false);
                audio_service_.EnableWakeWordDetection(audio_service_.IsAfeWakeWord());
            }
            // 只在从非 Speaking 状态进入时清空，避免跨句误清空
            if (previous_state != kDeviceStateSpeaking) {
                audio_service_.ResetDecoder();
            }
            break;
    }
}
```

### 3.1 ResetDecoder 调用条件

| 状态转换 | 是否调用 ResetDecoder | 原因 |
|---|---|---|
| Idle → Speaking | ✅ 调用 | 首次进入，清空旧音频 |
| Listening → Speaking | ✅ 调用 | 新对话开始，清空上一轮残留 |
| Speaking → Speaking | ❌ 不调用 | `SetDeviceState` 入口已 return |
| (没有 Speaking→Speaking 的 Schedule) | — | 状态不变不会进入 |

**当前代码 ResetDecoder 实现**（`audio_service.cc:627-635`）：

```cpp
void AudioService::ResetDecoder() {
    std::lock_guard<std::mutex> lock(audio_queue_mutex_);
    opus_decoder_->ResetState();
    timestamp_queue_.clear();
    audio_decode_queue_.clear();
    audio_playback_queue_.clear();
    audio_testing_queue_.clear();
    audio_queue_cv_.notify_all();
}
```

## 4. 固件收到 stop 后的行为

**文件**: `application.cc:461-470`

收到 `"stop"` 后固件的行为：
1. **不主动清空缓冲区** — ResetDecoder 仅在进入 Speaking 时调用，离开 Speaking 时不清空
2. **立即切换状态** — 通过 Schedule 将状态改为 Listening 或 Idle
3. **残留音频仍可播放** — 已入 decode/playback 队列的音频继续播放（队列不会被 stop 清空）
4. **拒绝新音频** — 状态变为 Listening 后，新的 Opus 音频将被 OnIncomingAudio 拒绝

**结论**：固件在收到 `stop` 后**不会中断正在播放的音频**，但会阻止后续新音频入队。

## 6. 结论：固件侧潜在问题

### ✅ 已修复的环节
1. **竞态条件**：`OnIncomingAudio` 已通过 `Schedule` 包裹，与 `"start"` 状态切换同步
2. **ResetDecoder 误清空**：已增加 `previous_state != kDeviceStateSpeaking` 条件

### ⚠️ 仍可能存在的问题
1. **`sentence_start` 和音频之间的关联**：固件不检查 `sentence_start` 和音频包的对应关系，只根据 `device_state_` 做门控。若服务端在 `stop` 后仍有音频到达（异常场景），会被丢弃
2. **音频队列满**：`MAX_DECODE_PACKETS_IN_QUEUE = 40`（2400ms / 60ms）。如果 TTS 音频流超过此值且后台消费慢，`PushPacketToDecodeQueue` 会返回 false（但不会阻塞，因为 `wait=false`）
3. **音频静默超时**：`AUDIO_POWER_TIMEOUT_MS = 15000`（15 秒），句间停顿超过 15 秒会关闭硬件输出（`audio_service.cc:644-645`）

### 最可能的丢包环节
**固件侧排查结论：当前代码已无严重逻辑错误。** 问题更可能出在服务端发送时序或网络传输层面。
