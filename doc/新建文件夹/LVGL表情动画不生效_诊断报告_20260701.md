## 3. 根本原因（Root Cause） ✔️ 已验证

### 3.1 `s_emoji_mutex` 从未初始化

**文件**: `ui_emoji_dualeye.cc` 行 46

```c
static SemaphoreHandle_t s_emoji_mutex = NULL;  // ← 初始化为 NULL，从未创建
```

该互斥量被声明为 `NULL`，且在整个文件中**没有任何位置调用 `xSemaphoreCreateMutex()`**。

### 3.2 影响范围

所有依赖此互斥量的函数均失效：

**`ui_emoji_set_expression`** — 行 251-252:
```c
void ui_emoji_set_expression(const char* name) {
    ESP_LOGI("EmojiDualEye", "🎯 set_expression called: %s", name ? name : "null");
    if (name == NULL || s_emoji_mutex == NULL) return;   // ← 行 251：提前返回
    if (name == NULL || s_emoji_mutex == NULL) return;   // ← 行 252：重复检查（疑似手误）
    // ↓ 以下代码永远不会执行 ↓
    strncpy(emoji_ctx.current_emoji_name, name, 31);
    emoji_ctx.target_type = (emoji_type_t)idx;
    emoji_ctx.needs_refresh = true;                      // ← 从不被设置
    ...
}
```

**`ui_emoji_update`** — 行 284:
```c
void ui_emoji_update(void) {
    ...
    if (s_emoji_mutex == NULL) return;                   // ← 提前返回
    if (emoji_ctx.needs_refresh) {                       // ← 从不被检查
        render_emoji_logic(type);                         // ← 从不被调用
    }
}
```

### 3.3 连锁效应

```
s_emoji_mutex = NULL
  → set_expression 提前返回
    → needs_refresh 永不为 true
      → ui_emoji_update 跳过 render_emoji_logic
        → anim_eye_to_state 从未被调用
          → lv_anim_start 从未被调用
            → 椭圆永远保持不变!
```

### 3.4 附注：`lv_anim_t` 复用模式本身是安全的

经过验证 LVGL v9 源码（`managed_components/lvgl__lvgl/src/misc/lv_anim.c` 行 94-111）：

```c
lv_anim_t * lv_anim_start(const lv_anim_t * a) {
    // 1. 先删除同(var, exec_cb)的现有动画
    if(a->early_apply && (a->exec_cb || a->custom_exec_cb)) {
        remove_concurrent_anims(a);
    }
    // 2. memcpy 复制到新节点，源 a 可复用
    lv_anim_t * new_anim = lv_ll_ins_head(anim_ll_p);
    lv_memcpy(new_anim, a, sizeof(lv_anim_t));
    // 3. early_apply 立即设置起始值
    new_anim->current_value = new_anim->path_cb(new_anim);
    if(new_anim->exec_cb) new_anim->exec_cb(new_anim->var, new_anim->current_value);
}
```

`lv_anim_start` 每次通过 `memcpy` 复制结构体到新分配的链表节点，不会依赖局部变量生命周期。`anim_eye_to_state` 中复用同一个 `lv_anim_t a` 调用 5 次 `lv_anim_start` 是 **正确的用法**，`remove_concurrent_anims` 也能正确处理不同 `exec_cb` 的并发。 ✔️ **此方向不是根因**

### 5.2 修复方案 B：使用原子操作替代互斥量（简化方案）🔧

对于单生产者-单消费者模型（一个写 `set_expression`，一个读 `update`），无需互斥量：

**文件**: `ui_emoji_dualeye.cc`

**步骤 1**: 移除互斥量声明和检查（行 46，251-252，284，268-272，289-292）

**步骤 2**: 修改 `ui_emoji_set_expression`：
```c
void ui_emoji_set_expression(const char* name) {
    ESP_LOGI("EmojiDualEye", "🎯 set_expression called: %s", name ? name : "null");
    if (name == NULL) return;

    int idx = -1;
    for (int i = 0; i < EMOJI_MAX; i++) {
        if (strcmp(name, emoji_names[i]) == 0) {
            idx = i;
            break;
        }
    }
    if (idx < 0) {
        name = "neutral";
        idx = EMOJI_NEUTRAL;
    }

    // ★ 无锁写入 —— 单消费者定时器读取，volatile 保证可见性
    strncpy(emoji_ctx.current_emoji_name, name, 31);
    emoji_ctx.target_type = (emoji_type_t)idx;
    emoji_ctx.needs_refresh = true;
    ESP_LOGI("EmojiDualEye", "✅ Set expression: %s (no mutex mode)", name);
}
```

**步骤 3**: 简化 `ui_emoji_update`：
```c
void ui_emoji_update(void) {

        ESP_LOGI("EmojiDualEye", "✅ render_emoji_logic 执行完成");

```

### 5.3 修复方案对比

| 维度 | 方案 A（互斥量） | 方案 B（无锁） |
|------|-----------------|---------------|
| 改动量 | +8 行 | -20 行 |

## 6. 问答汇总

### Q1: `lv_anim_start` 是否真的启动了动画？如何验证？

**答案**: ❌ 从未被调用。调用链在互斥量检查处断裂。可通过 `lv_anim_count_running(NULL)` 或 `lv_anim_get(obj, NULL)` 验证（详见 4.2）。

### Q2: `current_state` 是否正确传递到 `anim_eye_to_state`？

**答案**: ❌ `anim_eye_to_state` 从未被调用。即使被调用，`anim_eye_to_state` 行 81 会在动画前立即将 `current_state` 设为 `target`，这会覆盖中间值。**此设置方式本身也有问题**——眨眼逻辑依赖 `current_state.h` 作为起始值，但 `current_state` 在动画开始时就变成了目标值。但这是次要的，因为主函数从未执行。

### Q3: `eye_obj` 对象是否可能被其他 UI 元素覆盖或遮挡？

**答案**: ✅ **否**。`eye_obj` 在 `SetupUI()` 之后创建，默认在 z-order 顶层。`LcdDisplay::SetEmotion`（老系统）在 `DisplayManager::SetEmotion` 中被注释掉(行 53-58)。两个系统不冲突。原因为互斥量问题，非遮挡问题。

### Q4: 如何在 LVGL 中调试动画是否正在运行？

| 方法 | API | 说明 |
|------|-----|------|
| 获取某对象任意动画 | `lv_anim_t *a = lv_anim_get(obj, NULL)` | 返回 NULL 表示无动画 |
| 获取某对象指定动画 | `lv_anim_t *a = lv_anim_get(obj, anim_h_cb)` | 检查特定属性动画 |
| 全局动画计数 | `uint32_t cnt = lv_anim_count_running(NULL)` | 返回正在运行的动画数 |
| 删除某对象动画 | `lv_anim_delete(obj, NULL)` | 常用于重置状态后重测 |

## 8. 附录：LVGL v9 动画复用验证

来自 `managed_components/lvgl__lvgl/src/misc/lv_anim.c`:

```c
// 行 94-111
lv_anim_t * lv_anim_start(const lv_anim_t * a) {
    /*Do not let two animations for the same 'var' with the same 'exec_cb'*/
    if(a->early_apply && (a->exec_cb || a->custom_exec_cb)) {
        remove_concurrent_anims(a);           // 同(var, exec_cb)会被替换
    }
    lv_anim_t * new_anim = lv_ll_ins_head(anim_ll_p);
    lv_memcpy(new_anim, a, sizeof(lv_anim_t)); // 深度复制
    ...
    if(new_anim->early_apply) {
        new_anim->current_value = new_anim->path_cb(new_anim);
        if(new_anim->exec_cb) {
            new_anim->exec_cb(new_anim->var, new_anim->current_value); // 立即应用起始值
        }
    }
}
```

确认结论: `anim_eye_to_state` 中复用 `lv_anim_t a` 的写法是正确的。每次 `lv_anim_start` 都会 `memcpy` 复制结构体，局部变量 `a` 可以安全地修改并再次使用。不同 `exec_cb`（`anim_w_cb`, `anim_h_cb`, `anim_angle_cb`, `anim_x_cb`, `anim_y_cb`）对应不同属性动画，互不冲突。
