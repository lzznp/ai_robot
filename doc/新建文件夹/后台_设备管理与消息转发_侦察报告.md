### 3.3 超时检测机制

**文件**: `xiaozhi-server/core/connection.py` 第1704-1733行

```python
async def _check_timeout(self):
    """检查连接超时"""
    while not self.stop_event.is_set():
        last_activity_time = self.last_activity_time
        if self.need_bind:
            last_activity_time = self.first_activity_time

        if last_activity_time > 0.0:
            current_time = time.time() * 1000
            if current_time - last_activity_time > self.timeout_seconds * 1000:
                await self.close(self.websocket)
                break
        await asyncio.sleep(10)    # 每10秒检查一次
```

**超时配置**: `timeout_seconds = close_connection_no_voice_time + 60`

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `close_connection_no_voice_time` | 120 秒 | 无语音活动超时 |
| 额外冗余 | +60 秒 | 二道关闭保护 |
| **实际超时** | **180 秒** | 合计 |

### 3.4 资源清理 (close 方法)

```python
async def close(self, ws=None):
    """资源清理方法"""
    # 1. 释放 VAD 连接资源
    self.vad.release_conn_resources(self)

    # 2. 取消超时检测任务
    self.timeout_task.cancel()

    # 3. 清理工具处理器
    await self.func_handler.cleanup()

    # 4. 触发停止事件
    self.stop_event.set()

    # 5. 清空所有队列
    self.clear_queues()

    # 6. 关闭 WebSocket 连接
    await ws.close()

    # 7. 关闭 TTS/ASR 资源
    await self.tts.close()
    await self.asr.close()

    # 8. 关闭线程池
    self.executor.shutdown(wait=False)
```

### 4.4 MQTT 网关模式下的发送

**文件**: `xiaozhi-server/core/handle/sendAudioHandle.py` 第81-102行

```python
async def _send_to_mqtt_gateway(conn, opus_packet, timestamp, sequence):
    """发送带16字节头部的 opus 数据包给 mqtt_gateway"""
    header = bytearray(16)
    header[0] = 1                          # type
    header[2:4] = len(opus_packet)         # payload length
    header[4:8] = sequence                 # sequence
    header[8:12] = timestamp               # timestamp
    header[12:16] = len(opus_packet)       # opus length
    complete_packet = bytes(header) + opus_packet
    await conn.websocket.send(complete_packet)
```

**16字节头部格式**:

| 偏移 | 大小 | 字段 |
|------|------|------|
| 0 | 1 byte | type (固定 0x01) |
| 1 | 1 byte | 保留 |
| 2-3 | 2 bytes | payload length |
| 4-7 | 4 bytes | sequence (大端) |
| 8-11 | 4 bytes | timestamp (大端) |
| 12-15 | 4 bytes | opus 长度 (大端) |

MQTT 网关的音频接收入口：

**文件**: `xiaozhi-server/core/connection.py` 第527-565行

```python
async def _process_mqtt_audio_message(self, message):
    # 提取头部信息
    timestamp = int.from_bytes(message[8:12], "big")
    sequence = int.from_bytes(message[4:8], "big")
    payload_len = int.from_bytes(message[2:4], "big")
    audio_data = message[16:16 + payload_len]
    self.asr_audio_queue.put(audio_data)
```

## 六、设备识别与路由规则

### 6.1 设备唯一标识

设备的唯一标识是 **`device_id`**，通常为 MAC 地址格式（如 `a0:f2:62:e3:e0:d0`），从 HTTP 头部 `device-id` 获取。

### 6.2 消息中的目标设备提取

**标准消息流中，没有 `target` 或 `device_id` 字段。**

固件建立的是**一对一长连接**。每个 WebSocket 连接对应一个 `ConnectionHandler`，消息天然来自该设备，也默认发回该设备。

### 6.3 World 多角色系统中的路由

World 系统的路由规则基于**角色名 → MAC 地址的硬编码映射**：

```
角色名 → device-id 映射表  [connection.py:253-257]
  "Doly"       → "a0:f2:62:e3:e0:d0"   (双目屏)
  "瓦力"       → "a0:f2:62:e3:e0:d0"   (临时指向双目屏)
  "MOSS"       → "a0:f2:62:e3:e0:d0"   (临时指向双目屏)
```

路由优先级（`connection.py:276-291`）：

```
1. server.device_manager.get_connection(target_device_id)  [接口预留，未实现]
       ↓ (找不到)
2. 遍历 server.connections，匹配 device_id
       ↓ (找不到)
3. 回退到当前连接 self.websocket
```

### 6.4 默认路由规则

| 场景 | 规则 |
|------|------|
| 标准对话（无World） | **当前连接** → 谁发消息回复谁 |
| World 模式 | 按 **角色名映射** 查找设备，找不到用当前连接 |
| MQTT 网关 | 通过 MQTT broker 转发，服务器通过 `conn.websocket` 统一发送 |

## 七、认证与白名单

### 7.1 身份认证

**文件**: `xiaozhi-server/core/websocket_server.py` 第228-249行

```python
async def _handle_auth(self, websocket):
    if self.auth_enable:
        device_id = headers.get("device-id")
        client_id = headers.get("client-id")
        # 白名单设备 → 直接放行
        if self.allowed_devices and device_id in self.allowed_devices:
            return
        # 非白名单 → Bearer token 验证
        token = headers.get("authorization", "")
        auth_success = self.auth.verify_token(token, client_id=client_id, username=device_id)
```

**文件**: `xiaozhi-server/core/auth.py`

认证三元组：`(client_id, device_id, token)`，使用 HMAC-SHA256 签名。


## 九、关键发现

### 9.1 架构特点
- **纯内存管理**：`connections` 字典是唯一的设备注册表，没有 Redis 或数据库持久化
- **一对一长连接**：每个设备一个 WebSocket 连接，无消息队列中间件
- **无广播机制**：不存在 `broadcast` 函数，消息只发往当前连接

### 9.2 设备管理局限性
- `device_manager` 接口预留但**未实现**（`connection.py:278` 仅做 hasattr 检查）
- 设备能力信息 (`features`) 仅记录 MCP/emoji，无扩展能力描述
- 同一 `device_id` 再次连接时，旧连接不会被主动断开（先 `_handle_connection` 再 `finally` 清理旧连接）

### 9.3 World 多角色路由问题
- 角色名 → MAC 地址映射为**硬编码**（`connection.py:253-257`）
- 所有角色目前指向同一台设备（`a0:f2:62:e3:e0:d0`）
- 路由优先级中的 `server.device_manager` 接口未实现，会回退到遍历

### 9.4 消息序列化
- 控制消息：JSON（`type`, `state`, `text`, `session_id`）
- 音频消息：原始 Opus 二进制（普通 WS）或 16字节头部+Opus（MQTT）
- 所有下行消息都带 `session_id` 字段用于关联
