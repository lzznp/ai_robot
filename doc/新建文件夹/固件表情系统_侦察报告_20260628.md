## 2. 表情触发机制

### 2.1 数据流：`{"type":"llm","emotion":"happy"}` → 屏幕显示

```

  │    → 遍历 LLM 回复文本中的 emoji 字符

  │    → 发送 {"type":"llm","emotion":"happy","text":"🙂"}   [connection.py:1209]
  │
  ▼

  │
  │  OnIncomingJson → type="llm"                   [application.cc:493-499]
  │    → Schedule(display->SetEmotion("happy"))

  ▼

  │
  │  EmoteDisplay::SetEmotion("happy")            [emote_display.cc:390-412]

  │

```

### 2.2 服务端 emotion 映射

**文件**: `core/utils/textUtils.py:8-30`

```python
EMOJI_MAP = {
    "😂": "funny",    "😭": "crying",    "😠": "angry",
    "😔": "sad",      "😍": "loving",    "😲": "surprised",
    "😱": "shocked",  "🤔": "thinking",  "😌": "relaxed",
    "😴": "sleepy",   "😜": "silly",     "🙄": "confused",
    "😶": "neutral",  "🙂": "happy",     "😆": "laughing",
    "😳": "embarrassed", "😉": "winking", "😎": "cool",
    "🤤": "delicious", "😘": "kissy",    "😏": "confident",
}
```

**映射逻辑**: 当 LLM 回复文本中出现上述 emoji 字符时，取**第一个**匹配的 emoji，将其映射值作为 `"emotion"` 值下发。**没有出现的 emoji 则不触发**。

## 3. 表情显示机制

### 3.1 EmoteDisplay::SetEmotion 实现

**文件**: `main/display/emote_display.cc:390-412`

```cpp
void EmoteDisplay::SetEmotion(const char* const emotion)
{
    if (!emotion) return;

    ESP_LOGI(TAG, "SetEmotion: %s", emotion);
    if (!engine_) return;

    // 从已加载的资产中查找该表情名称
    const AssetData emoji_data = GetEmojiData(emotion);
    bool repeat = emoji_data.loop;       // 是否循环
    int fps = emoji_data.fps > 0 ? emoji_data.fps : 20;

    // idle 和 neutral 不循环
    if (std::strcmp(emotion, "idle") == 0 || std::strcmp(emotion, "neutral") == 0) {
        repeat = false;
    }

    DisplayLockGuard lock(this);
    engine_->SetEyes(emotion, repeat, fps, this);
}
```

### 3.2 EmoteEngine 渲染

**文件**: `main/display/emote_display.cc:310-332`

- 使用 GFX 图形库（非 LVGL）
- 通过 `gfx_anim_set_src()` 加载 `.eaf` 动画数据
- 通过 `gfx_anim_set_segment()` 设置 fps 和循环模式
- 通过 `gfx_anim_start()` 启动动画
- 支持**循环/不循环**两种模式
- 支持**多帧动画**（由 `.eaf` 文件格式提供）
- **不支持**跨表情的过渡动画（切换时直接停止旧动画，启动新动画）

### 3.3 显示模式

| UIDisplayMode | 触发状态 | 显示内容 |
|---|---|---|
| `SHOW_LISTENING` | Listening | 眼部动画(强制 happy) + 麦克风图标 |
| `SHOW_TIME` | Idle/Standby | 电池图标 + 时钟 |
| `SHOW_TIPS` | Speaking + all others | 对话气泡 + 状态图标 |

### 4.2 缺失项分析

| 缺失项 | 原因 | 影响 |
|---|---|---|
| `"cool"` (😎) | 服务端有映射，但 emote.json 没有 | 😎→ "cool" 下发后，固件找不到对应 emoji data，仅打 WARN 日志 |
| `"kissy"` (😘) | 服务端有映射，但 emote.json 没有 | 同上 |
| 独立 `"idle"` 动画 | emote.json 有映射，但服务端不能触发 | idle 表用于 Standby 状态，目前由固件内部触发 |
| 多个表情共用同一 .eaf | emote.json 中 8 个表情共享 `Happy.eaf` | 这些表情播放相同的动画，无法区分 |

### 4.3 资源文件现状（.eaf 文件）

`.eaf` 文件并非源代码中的 `.c` 或 `.bin` 文件，而是在编译时通过 `scripts/spiffs_assets/build.py` 从 `emote.json` 配置构建到 SPIFFS 分区的资产。实际 `.eaf` 文件存放在 `assets` 目录下的板卡特定子目录中，需要查看 `esp32-firmware/scripts/spiffs_assets/` 来确认。
