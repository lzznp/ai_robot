## 1. esp32_camera.h 是否存在

### 搜索结果

| 搜索路径 | 结果 |

| `main/boards/common/` | ✅ **存在** — `esp32-firmware/main/boards/common/esp32_camera.h` |
| `managed_components/` | ❌ 不存在 |

### 文件内容说明

`esp32_camera.h` 定义了一个 `Esp32Camera` 类，它继承自 `Camera` 基类。构造函数签名使用 **新框架类型**：

```cpp
// main/boards/common/esp32_camera.h:45
Esp32Camera(const esp_video_init_config_t& config);
```

- 内部包含头文件：`camera.h`, `esp_video_init.h`, `jpg/image_to_jpeg.h`
- 使用 `esp_video_init()`（来自 `espressif__esp_video` 组件）完成摄像头初始化
- **不使用** `camera_config_t`、`PIXFORMAT_*`、`FRAMESIZE_*` 等旧 API 类型

## 2. camera_config_t 类型在哪里定义

### 项目内搜索：`struct camera_config_t` / `typedef.*camera_config_t`

```
未在项目任何文件中找到匹配。
```

### 结论

`camera_config_t` **在项目范围内未被定义**。

它是[乐鑫 `esp32-camera` 库](https://github.com/espressif/esp32-camera)（`esp_camera.h`）中的类型，该库是 **Arduino 风格** 的老版摄像头驱动，与本项目使用的 `esp_video` / `esp_cam_sensor` 新框架 **不兼容**。

本项目通过 `managed_components/espressif__esp_video/` 组件管理摄像头，使用 `esp_video_init_config_t` 替代 `camera_config_t`。

### 替代类型

| 旧类型 | 新类型 | 头文件 |
|---|---|---|
| `camera_config_t` | `esp_video_init_config_t` | `esp_video_init.h` |
| — | `esp_video_init_dvp_config_t` | `esp_video_init.h` |
| — | `esp_video_init_sccb_config_t` | `esp_video_init.h` |
| — | `esp_cam_ctlr_dvp_pin_config_t` | `esp_cam_ctlr_dvp.h` |

| 宏 | 项目内搜索 | 来源库 |
|---|---|---|

| `FRAMESIZE_VGA` | 未定义 | `esp32-camera` 库的 `sensor.h` |

| `CAMERA_GRAB_WHEN_EMPTY` | 未定义 | `esp32-camera` 库的 `esp_camera.h` |

**这四个宏均未在本项目中被定义。** 它们属于已废弃的外部库 `esp32-camera`（`idf_component.yml` 名为 `espressif/esp32-camera`），本项目并未依赖该组件。

> 注：`managed_components` 下只有与 **新框架** 对应的同名常量（如 `ESP_CAM_SENSOR_PIXFORMAT_RGB565`），但它们的类型、枚举值和用法与旧宏不同，不能混用。

## 4. 带摄像头板子的处理方式对照

### 4.1 正确做法的示例板子

以下板子都有摄像头且编译通过，均使用 **新框架** `esp_video_init_*` 系列类型：

| 板卡 | 文件 |
|---|---|

| `df-k10` | `main/boards/df-k10/df_k10_board.cc` |

### 4.2 正确做法的头文件包含

```cpp
#include "esp32_camera.h"           // Esp32Camera 类
// esp_video_init.h 由 esp32_camera.h 间接包含
```

不需要包含 `esp_camera.h` 或任何旧库头文件。

### 4.3 正确做法的初始化代码（以 `atk-dnesp32s3` 为例）

```cpp
// atk_dnesp32s3.cc:142-182
void InitializeCamera() {
    // 1. 配置 DVP 引脚
    static esp_cam_ctlr_dvp_pin_config_t dvp_pin_config = {
        .data_width = CAM_CTLR_DATA_WIDTH_8,
        .data_io = { [0]=CAM_PIN_D0, [1]=CAM_PIN_D1, ..., [7]=CAM_PIN_D7 },
        .vsync_io = CAM_PIN_VSYNC,
        .de_io = CAM_PIN_HREF,
        .pclk_io = CAM_PIN_PCLK,
        .xclk_io = CAM_PIN_XCLK,
    };

    // 2. 配置 SCCB (I2C)
    esp_video_init_sccb_config_t sccb_config = {
        .init_sccb = true,
        .i2c_config = { .port = 1, .scl_pin = CAM_PIN_SIOC, .sda_pin = CAM_PIN_SIOD },
        .freq = 100000,
    };

    // 3. 配置 DVP 控制器
    esp_video_init_dvp_config_t dvp_config = {
        .sccb_config = sccb_config,
        .reset_pin = CAM_PIN_RESET,
        .pwdn_pin = CAM_PIN_PWDN,
        .dvp_pin = dvp_pin_config,
        .xclk_freq = 20000000,
    };

    // 4. 配置 esp_video 初始化参数
    esp_video_init_config_t video_config = {
        .dvp = &dvp_config,
    };

    // 5. 创建 Esp32Camera 实例
    camera_ = new Esp32Camera(video_config);
}
```

### 4.4 CMakeLists.txt 特殊配置

**无特殊配置。** `main/CMakeLists.txt` 第 43-45 行自动编译 `boards/common/*.cc` 中的通用文件（含 `esp32_camera.cc`）：

## 5. 根因分析与修复方案

### 根因

`lingkong-s3-moc-cam-1.54tft.cc` 中的 `InitializeCamera()` 函数（第 174-208 行）使用了 **废弃的 `esp32-camera` 旧 API**：

```cpp
// 问题代码 — 使用了不存在的旧类型和宏
camera_config_t config = {};                    // ← 不存在
config.pixel_format = PIXFORMAT_RGB565;         // ← 不存在
config.frame_size = FRAMESIZE_VGA;              // ← 不存在
config.fb_location = CAMERA_FB_IN_PSRAM;        // ← 不存在
config.grab_mode = CAMERA_GRAB_WHEN_EMPTY;      // ← 不存在
camera_ = new Esp32Camera(config);              // ← 类型不匹配（接受 esp_video_init_config_t）
```

### 修正方法

将 `InitializeCamera()` 重写为项目标准模式，使用 `esp_video_init_*` 系列类型。以下是对应的修正代码：

```cpp
void InitializeCamera() {
    tca6408_->SetOutputState(3, 0);
    vTaskDelay(100);
    tca6408_->SetOutputState(3, 1);
    tca6408_->SetOutputState(2, 0);

    esp_cam_ctlr_dvp_pin_config_t dvp_pin_config = {
        .data_width = CAM_CTLR_DATA_WIDTH_8,
        .data_io = {
            [0] = CAMERA_PIN_D0,
            [1] = CAMERA_PIN_D1,
            [2] = CAMERA_PIN_D2,
            [3] = CAMERA_PIN_D3,
            [4] = CAMERA_PIN_D4,
            [5] = CAMERA_PIN_D5,
            [6] = CAMERA_PIN_D6,
            [7] = CAMERA_PIN_D7,
        },
        .vsync_io = CAMERA_PIN_VSYNC,
        .de_io = CAMERA_PIN_HREF,
        .pclk_io = CAMERA_PIN_PCLK,
        .xclk_io = CAMERA_PIN_XCLK,
    };

    esp_video_init_sccb_config_t sccb_config = {
        .init_sccb = true,
        .i2c_config = {
            .port = 1,
            .scl_pin = CAMERA_PIN_SIOC,
            .sda_pin = -1,   // 使用已初始化的 I2C 总线
        },
        .freq = 100000,
    };

    esp_video_init_dvp_config_t dvp_config = {
        .sccb_config = sccb_config,
        .reset_pin = CAMERA_PIN_RESET,
        .pwdn_pin = CAMERA_PIN_PWDN,
        .dvp_pin = dvp_pin_config,
        .xclk_freq = XCLK_FREQ_HZ,
    };

    esp_video_init_config_t video_config = {
        .dvp = &dvp_config,
    };

    camera_ = new Esp32Camera(video_config);
}
```

### 需要检查的其他注意事项

1. **SCCB I2C 端口**：确认 `sccb_config.i2c_config.port` 是否与已有 I2C 总线冲突（`config.h` 中 `CAMERA_PIN_SIOD=GPIO_NUM_21` 与 `AUDIO_CODEC_I2C_SDA_PIN` 共用，需确认复用逻辑）。
2. **`pin_sccb_sda = -1`**：旧代码中 `pin_sccb_sda = -1` 表示复用已初始化的 I2C，新框架通过 `sccb_config.i2c_config.sda_pin` 直接指定引脚或 `i2c_handle`。
3. **`#include` 不需改动**：已有的 `#include "esp32_camera.h"` 已足够。
