## 3. TTS 实际发送目标

### 3.1 日志 "未找到设备 a0:f2:62:e3:e0:d0，使用当前连接" 的原因

这条日志由 `receiveAudioHandle.py:112` 输出：

```python
device_conn = conn
conn.logger.warning(f"未找到设备 {target_device_id}，使用当前连接")
```

**`conn` 是 `admin_mic`（GUI 连接）**。所以：

| 项目 | 实际值 |
|---|---|
| TTS 文本状态 (`sentence_start`) 发给了 | ✅ **GUI 连接 (admin_mic)** 的 WebSocket |
| TTS 音频流 (`tts_one_sentence`) 通过 | ✅ **GUI 连接 (admin_mic)** 的 TTS 线程 |
| 物理设备 (`a0:f2:62:e3:e0:d0`) | ❌ **从未收到任何 TTS 数据** |

### 3.2 为什么退出时能播报

退出时（end_prompt）走的是 `startToChat` → `send_stt_message(conn, ...)` → `conn.executor.submit(conn.chat, ...)`。

这个路径使用的是 `conn` — 也就是设备连接本身（因为退出时 GUI 可能已断开，设备仍在连接），所以 TTS 正常发给设备。

**但 GUI 输入时**，`conn` 是 GUI 连接 (admin_mic)，所以 TTS 发给了 GUI。

### 3.3 为什么 GUI 能看到 TTS

因为 `send_stt_message(device_conn, response_text)` 最终调用 `device_conn.websocket.send()`，而 `device_conn` 回退为了 GUI 连接的 ConnectionHandler，所以 `device_conn.websocket` 就是 GUI 的 WebSocket。

## 4. 修复方案

### 方案 A（推荐）：给 WebSocketServer 添加连接追踪

**文件**: `core/websocket_server.py`

```python
class WebSocketServer:
    def __init__(self, config: dict):
        # ...
        self.connections = {}  # ★ 新增：device_id → ConnectionHandler

    async def _handle_connection(self, websocket):
        # ... 认证 ...
        handler = ConnectionHandler(...)
        self.connections[handler.device_id] = handler  # ★ 注册
        try:
            await handler.handle_connection(websocket)
        finally:
            # handler 退出时清理
            if handler.device_id in self.connections:
                del self.connections[handler.device_id]
```

### 方案 A 同时在 receiveAudioHandle.py 使用

