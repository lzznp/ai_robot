```python
async def no_voice_close_connect(conn, have_voice):

        conn.last_activity_time = time.time() * 1000
        return

            if not prompt:
                prompt = "请你以```时间过得真快```未来头，用富有感情、依依不舍的话来结束这场对话吧。！"
            await startToChat(conn, prompt)  # ← 关键：把 end_prompt 文本当作 ASR 结果送入 startToChat
```

## 2. 代码路径对比：正常对话 vs end_prompt

### 2.1 正常对话

```
语音输入 → handleAudioMessage → VAD检测 → ASR转文字 → handle_voice_stop
  → startToChat(conn, text)
    → send_stt_message(conn, text)       ← 发送 "stt" + "start"
    → conn.executor.submit(conn.chat, text) ← LLM 处理
      → FIRST + MIDDLE×N + LAST
```

### 2.2 end_prompt 对话

```
超时检测 → no_voice_close_connect
  → startToChat(conn, prompt)             ← prompt 是 end_prompt 文本
    → send_stt_message(conn, prompt)      ← 发送 "stt" + "start"
      → 特殊分支: 如果 prompt 与 end_prompt 文本匹配
        → 只发 "start"（不发"stt"），return
    → conn.executor.submit(conn.chat, prompt) ← LLM 处理
      → FIRST + MIDDLE×N + LAST
```

### 2.3 关键差异

| 环节 | 正常对话 | end_prompt |
|---|---|---|
| 触发方式 | VAD + ASR | 超时检测 |
| CALLER | `handle_voice_stop` | `no_voice_close_connect` |
| `send_stt_message` | 完整发送 `stt`+`start` | 特殊分支：仅发 `start`（跳过 `stt`） |
| `client_is_speaking` | 设为 True | **不设**（`send_stt_message` 提前 return） |
| `chat()` 调用 | ✅ 有 | ✅ 有 |
| `close_after_chat` | False | **True**（在 no_voice_close_connect 中设置） |
| TTS 流程 | FIRST → MIDDLE → LAST | FIRST → MIDDLE → LAST |
| 连接关闭 | 不关闭 | LAST 发送后关闭 WebSocket |

### 2.4 send_stt_message 的 end_prompt 特殊分支

**文件**: `core/handle/sendAudioHandle.py:302-310`

```python
async def send_stt_message(conn, text):
    end_prompt_str = conn.config.get("end_prompt", {}).get("prompt")
    if end_prompt_str and end_prompt_str == text:
        await send_tts_message(conn, "start")
        return  # ★ 提前返回！不设 client_is_speaking！
```

**影响**: `client_is_speaking` 保持为 False。但 `chat()` 中的 `client_abort` 和音频流不受此影响。

### 2.5 close_after_chat 的连锁反应

**文件**: `core/handle/sendAudioHandle.py:50-53`

```python
if sentenceType == SentenceType.LAST:
    await send_tts_message(conn, "stop", None)  # ← 等待音频完成 → 发 "stop"
    if conn.close_after_chat:                   # ← end_prompt 时为 True
        await conn.close()                      # ← 关闭 WebSocket！
```

关闭 WebSocket 后，固件的 `OnAudioChannelClosed` 被触发：

**文件**: `esp32-firmware\main\application.cc:444-451`

```cpp
protocol_->OnAudioChannelClosed([this, &board]() {
    board.SetPowerSaveMode(true);
    Schedule([this]() {
        SetDeviceState(kDeviceStateIdle);  // ← 强制回到 Idle 状态
    });
});
```

**时序**: `"stop"` → `_wait_for_audio_completion`（阻塞直到音频发完）→ 发 `"stop"` JSON → `await conn.close()` → 触发 `OnAudioChannelClosed` → Schedule `SetDeviceState(Idle)`。

**结论**: `close_after_chat` 的关闭发生在所有音频发送完毕之后，不影响本轮的 TTS 播放。

## 3. TTS 分句核心逻辑

### 3.1 文本分句的两个阶段

**阶段 1**: `tts_one_sentence()` — 按标点将回复文本切分成多个 MIDDLE 条目

**文件**: `core/providers/tts/base.py:276-302`

```python
def tts_one_sentence(self, conn, content_type, content_detail=None, ...):
    # ★ 不判断是否已有 FIRST/LAST，直接按标点切分
    segments = re.split(r"([。！？!?；;\n])", content_detail)
    for seg in segments:
        self.tts_text_queue.put(TTSMessageDTO(
            sentence_id=sentence_id,
            sentence_type=SentenceType.MIDDLE,   # ← 全部分配为 MIDDLE
            content_type=content_type,
            content_detail=seg,
        ))
```

**阶段 2**: `_get_segment_text()` — 从累积的文本缓冲中按标点提取完整句子交给 TTS 引擎

**文件**: `core/providers/tts/base.py:483-520`

```python
self.punctuations = ("。", "！", "？", "!", "?", ";", "；", "\n")
self.first_sentence_punctuations = ("。", "！", "？", "!", "?", ";", "；", "\n", "，", ",", "、", "：", ":")
```

- **第一句**: 宽松标点集（含逗号、顿号、冒号），让第一句尽早开始
- **后续句子**: 严格标点集（仅句号、感叹号、问号、分号、换行）

### 3.2 FIRST/MIDDLE/LAST 的分配规则

| SentenceType | 分配位置 | 条件 | 次数/轮 |
|---|---|---|---|
| **FIRST** | `chat()` depth=0 入口 | **必须** depth==0 | 1 次 |
| **MIDDLE** | LLM 流式 token + `tts_one_sentence()` | 非 tool_call 的流式内容 | N 次 |
| **LAST** | `chat()` depth=0 结尾 | **必须** depth==0 | 1 次 |

**核心约束**: 只有 `depth==0` 的 `chat()` 才会产生 FIRST 和 LAST。递归调用（`depth>0`）**不产生** FIRST/LAST。

### 3.3 多句 TTS 的连续性

**问**: 多句 TTS 是否在同一轮对话中连续下发？
**答**: ✅ **是**。所有 MIDDLE 内容（包括多轮 LLM 回复、工具调用结果）共用顶层 `depth=0` 的 FIRST 和 LAST，音频连续发送，中间不插入 `"stop"`/`"start"`。

## 4. 固件 TTS 接收对照

### 4.1 当前固件状态

**OnIncomingAudio**（`application.cc:425-433`）— **已修复**：

```cpp
protocol_->OnIncomingAudio([this](std::unique_ptr<AudioStreamPacket> packet) {
    AudioStreamPacket* raw_packet = packet.release();
    Schedule([this, raw_packet]() {
        std::unique_ptr<AudioStreamPacket> p(raw_packet);
        if (device_state_ == kDeviceStateSpeaking) {
            audio_service_.PushPacketToDecodeQueue(std::move(p));
        }
    });
});
```

- 使用 `Schedule` 包裹，与状态切换同步
- 仅当 `device_state_ == Speaking` 时入队

**ResetDecoder**（`application.cc:729-732`）— **已修复**：

```cpp
case kDeviceStateSpeaking:
    ...
    if (previous_state != kDeviceStateSpeaking) {
        audio_service_.ResetDecoder();
    }
    break;
```

- **条件化清除**: 仅从非 Speaking 状态进入时清空队列
- 跨句 `Speaking→Listening→Speaking` 时不清空（防止误清正在播放的队列）

**收到 `"stop"` 后行为**（`application.cc:465-470`）：

```cpp
// 仅切换状态，不清空音频队列
SetDeviceState(kDeviceStateListening);
```

- 已入队的音频继续播放
- 后续新音频被拒绝（因为状态已不是 Speaking）

### 4.2 是否支持多句连续播放

| 场景 | 结果 | 原因 |
|---|---|---|
| 单次 `"start"` + 多句音频 + 一次 `"stop"` | ✅ 支持 | Speaking 状态持续，所有音频入队 |
| 两次 `"start"` + 各自音频 + 一次 `"stop"` | ⚠️ 依赖条件化 ResetDecoder | 已修复，第二次 `"start"` 不触发 ResetDecoder |

## 5. 结论：原生 bug vs 我们的修改

### 5.1 关键修改点对比

**原始代码基线（xiaozhi/tenclass 开源版）**：

| 文件 | 行号 | 原始代码 | 我们的修改 |
|---|---|---|---|
| `receiveAudioHandle.py` | 9-21 | 无 World 导入 | 新增 World、Character 导入；新增第 9-10 行"修复导入路径"注释 |
| `receiveAudioHandle.py` | 90-109 | `# 原有逻辑：走 LLM 流程` 直接接第 112 行 | **新增 World 多角色调度** |
| `receiveAudioHandle.py` | 111 | 原第 90 行 | 新增注释标记 |

**World 多角色调度**（`receiveAudioHandle.py:90-109`）：

```python
# ========== World 多角色调度 ==========
if hasattr(conn, 'world') and conn.world:
    results = conn.world.process(actual_text)
    if results:
        for result in results:
            if ": " in result:
                name, response_text = result.split(": ", 1)
                await send_stt_message(conn, response_text)  # ★ 每角色发一次 "start"
                conn.tts.tts_one_sentence(conn, ContentType.TEXT, content_detail=response_text)
                await asyncio.sleep(3)                       # ★ 每角色之间等待 3 秒

        conn.tts.tts_audio_queue.put((SentenceType.LAST, [], None, None))  # ★ 手动 LAST
        return
```

### 5.2 判定结论

**这是我们的修改导致的，不是原生 bug。**

| 判定项 | 结果 | 证据 |
|---|---|---|
| 原生 end_prompt TTS 流程 | ✅ **无 bug** | 正常的 `startToChat → chat() → FIRST→MIDDLE→LAST` 链路，所有音频在一个 Speaking 周期内连续下发 |
| 原生正常对话 TTS 流程 | ✅ **无 bug** | 同上路径 |
| **World 多角色调度** | ❌ **有 bug** | 每角色调用一次 `send_stt_message`（发多次 `"start"`）；每角色调用 `tts_one_sentence`（只有 MIDDLE，无 FIRST）；手动插入 `LAST` |

### 5.3 World 修改的潜在问题

| 问题 | 影响 | 严重程度 |
|---|---|---|
| **每角色发一次 `"start"`** | 固件重复进入 Speaking（但已条件化 ResetDecoder，不触发清空） | 低 |
| **无 FIRST 信号** | `tts_text_priority_thread` 中 `processed_chars` 未重置、`tts_text_buff` 未清空 | **中** |
| **手动 LAST 无 sentence_id** | `conn.tts.tts_audio_queue.put((SentenceType.LAST, [], None, None))` — sentence_id 为 None | **中** |
| **多角色间 3 秒睡眠** | TTS 音频在事件循环中产生间隙，网络层面能到但播放不连续 | 低 |
| **跳过了 LLM `chat()`** | 不打对话历史、不做意图识别、不触发工具调用 | 功能差异 |

### 5.4 修复建议

#### 修复 A（World 多角色调度 — 核心）

将 `receiveAudioHandle.py:90-109` 的 World 路径改为通过一次 `chat()` 发送，而不是逐角色手动发 TTS：

```python
# 方案：将所有角色的回复合并后通过 chat() 统一发送
if hasattr(conn, 'world') and conn.world:
    results = conn.world.process(actual_text)
    if results:
        combined_text = " ".join(...)  # 合并所有角色回复
        conn.executor.submit(conn.chat, combined_text)  # 走正常 chat 路径
        return
```

或者保持分角色播放但修正缺少 FIRST 的问题：

```python
# 方案：手动补 FIRST，修复 sentence_id
if hasattr(conn, 'world') and conn.world:
    results = conn.world.process(actual_text)
    if results:
        sentence_id = str(uuid.uuid4().hex)
        conn.sentence_id = sentence_id
        conn.tts.tts_text_queue.put(TTSMessageDTO(
            sentence_id=sentence_id,
            sentence_type=SentenceType.FIRST,
            content_type=ContentType.ACTION,
        ))
        for result in results:
            if ": " in result:
                name, response_text = result.split(": ", 1)
                conn.tts.tts_one_sentence(conn, ContentType.TEXT, content_detail=response_text)
        conn.tts.tts_text_queue.put(TTSMessageDTO(
            sentence_id=sentence_id,
            sentence_type=SentenceType.LAST,
            content_type=ContentType.ACTION,
        ))
        return
```

#### 修复 B（send_stt_message 在 end_prompt 路径 — 可选）

`sendAudioHandle.py:302-310` 中 end_prompt 提前 return 导致 `client_is_speaking` 不更新，虽然不影响播放但可能导致状态不一致：

```python

    await send_tts_message(conn, "start")
    return

# 修改后
if end_prompt_str and end_prompt_str == text:
    await send_tts_message(conn, "start")
    conn.client_is_speaking = True  # ★ 补上
```

## 6. 完整时序对照图

```
正常对话（原生代码）:
  t0: 用户语音 → ASR → "天气怎么样？"
  t1: send_stt_message → {"type":"stt","text":"天气怎么样？"}
  t2:                    {"type":"tts","state":"start"}        → [Schedule] → Speaking
  t3: chat() → FIRST (ACTION)  → TTS文本队列
  t4: LLM流式 → MIDDLE×N       → TTS文本队列
  t5: TTS线程: MIDDLE文本 → to_tts_stream() → Opus音频 → 音频队列
  t6: 音频线程: sendAudioMessage(MIDDLE, opus, text)
  t7:                              → Opus binary × M           → 固件接收播放
  t8: chat结束 → LAST (ACTION) → TTS文本队列
  t9: TTS线程: LAST → 处理剩余文本 → 音频队列 LAST
  t10: 音频线程: LAST → send_tts_msg("stop")
  t11:                              → {"type":"tts","state":"stop"} → [Schedule] → Listening
  ─── 所有音频连续播放 ✅

end_prompt（原生代码）:
  t0: 120秒超时 → no_voice_close_connect
  t1: startToChat(conn, prompt)
  t2: send_stt_message → {"type":"tts","state":"start"}      → [Schedule] → Speaking
  t3+ ... 同正常对话 ...
  ─── 与正常对话路径相同 ✅

World 多角色（我们的修改）:
  t0: 用户语音 → "和角色A、角色B聊"
  t1: startToChat(conn, text)
  t2: send_stt_message → {"type":"stt","text":"和角色A、角色B聊"}
  t3:                    {"type":"tts","state":"start"}        → [Schedule] → Speaking
  t4: [World path]
  t5: send_stt_message("角色A的回复") → {"type":"tts","state":"start"} → no-op(已是Speaking)
  t6: tts_one_sentence("角色A的回复") → MIDDLE文本 → TTS队列
  t7: asyncio.sleep(3)
  t8: send_stt_message("角色B的回复") → {"type":"tts","state":"start"} → no-op
  t9: tts_one_sentence("角色B的回复") → MIDDLE文本 → TTS队列
  t10: conn.tts.tts_audio_queue.put(LAST, [], None, None)     → "stop"
  t11:                              → {"type":"tts","state":"stop"} → [Schedule] → Listening
  ───────────────────────────────────────────────────────────────────────────────────────
  ⚠️ 问题1: 无 FIRST → tts_text_buff 未清空、processed_chars 未重置
  ⚠️ 问题2: LAST 的 sentence_id=None → 可能被 sentence_id 过滤丢弃
  ⚠️ 问题3: 每角色之间 3 秒间隔 → 播放不连续
```
